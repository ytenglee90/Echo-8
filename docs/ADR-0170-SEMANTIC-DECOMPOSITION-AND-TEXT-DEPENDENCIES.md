# ADR 0170 · 自然语言意图拆解与正文结果依赖

有效，补充 ADR 0162、0166、0167、0169。用户要求完善通用的自然语言动作拆解与本地解析，不能只修复某个改写句式。AI 助手拥有拆解、映射和正文准备；共享服务仅验证纯数据。原功能所有者继续负责真实执行、校验、事务、历史和持久化。

## 两阶段模型兜底

完整本地指令优先。未编译的应用请求先由当前选中的已配置模型做独立语义拆解，只发送当前用户原话与逐项要求，不发送动作目录或画布数据。内部意图图 v1 区分查询、控制、创建、正文处理、写入、修改和删除，保留动作要求、来源/目标角色、前置结果引用、输出类型和依赖，逐项覆盖原句。它是用户可理解的动作数据，不是模型思考过程，也不能执行。

随后才读取动作目录及既有有界元数据进行映射，沿用内部工作区计划传输 v2。已确定的本地动作不能在拆解中丢失；同一个原句可以拆成多个意图，多个字段也可以共同限定一个动作。映射必须覆盖全部意图，不允许不同独立动作共用同一步冒充完整覆盖，保留依赖先后；原条件、所有者前置和回执校验继续有效。模型解释、占位内容和成功声明不成为执行证据。

拆解格式错误与映射漏项共享一次修正机会；整句最多四次语义模型调用，包括拆解、可选筛选、修正及观察反馈。常规兜底比原先增加一次有界拆解请求，通常两次，目录需要筛选时三次；完整本地操作仍为零。复杂请求预算不足则停止，不能无限补查。正文生成是另外一次明确的创作请求，费用全部进入原请求检查和 Token 账本。取消、选区变化、对象修订和重复执行保护沿用原任务与所有者。

## 正文工作流编译

内部 `text.composeAndWrite` 仅是 AI 编译器的映射描述，不注册公共可执行动作。正文写入新对象明确包含创建对象、读取并处理来源正文、把处理结果填入新对象三个意图；写入已有节点为处理与写入两个意图。创建/处理的结果通过 `targetFrom` / `textFrom` 引用。模型必须完整绑定，不能以一个创建动作漏掉正文生成或填入，也不能用该工作流冒充额外删除、控制等尚未编译的动作；暂不支持的混合会明确停止整份计划。

解析阶段不读取正文。应用在语义计划通过后，按公开 context 能力定位并读取指定来源，校验隐私、唯一性、修订和上下文预算（保留单来源 8,192 字符及总预算），把已绑定来源交给当前模型生成结构化实际正文。只发送必要来源，已有目标追加所需证据仍受预算保护。模型不能决定 ID、写入范围、事务或执行状态。

正文成功后才编译既有画布计划：新建与实际正文同一原子事务提交，失败不留下空对象；已有内容修改仍需原确认。来源与目标修订在写入前复查，一次撤销恢复。用户未提供新标题时，应用采用“来源标题 · 处理类型结果”的可见默认值，重名仍由原创建所有者分配。只有完整来源或受审范围可参与，不放宽大型正文与私有节点边界。

本地规则采用可交换的来源、处理方式、目标和标题字段，支持多个内容处理动词、填入/插入/写入及显式结果引用，不在“改写”内部匹配“写”。已生成且可完整核对的当前对话草稿可按明确要求原样写入，零模型调用；缺失、截断或无关对话不猜测。“见下方正文”等独立占位内容不能作为实际正文。

## 通用本地组合

补齐并列编辑器、并列功能面板、无标点连续动作和打开后进入沉浸的指代。完整编译全部子句；不能把后续动词吞成目标标题。引号名称保留，真实包含“和”的标题在目录复查时按字面优先；多对象后的单数指代不猜测。陌生正文处理并写入请求进入整句语义兜底，无法完整匹配不会提前返回“只在本地处理”。

## 兼容与验证

没有新增公共协议、文件格式或数据库字段，无迁移，不部署个人数据 Worker。内部语义图不进入书籍、连接备份或个人配置。生成单 HTML 仍从同一源码构建。

验证包括通用的一句多动作、不同动作不能共用一步、语义依赖与结果类型、三步正文链、已有目标追加、所有字段顺序与多个处理动词、引号与同名、完整草稿零模型复用、占位拒绝、原子撤销、修订与取消以及请求正文隔离。浏览器模型响应使用模拟，不能据此声称任意模型或任意自然语言已能完美理解；实际模型能力与未实现功能仍会明确失败或澄清。
