# ADR-0061：可热插拔的文本纠错、节点引用与补全

## 状态

已采纳。本文最初误用了已存在的 ADR-0034 编号；2026-09-28 仅更正为唯一编号 ADR-0061，不改变原决策或兼容性。

## 问题

文本编辑区需要提供纠错建议、画布节点标题引用和输入补全，但这些能力不能直接写死在编辑器的数据层，也不能在每次键入时扫描整篇超长正文或直接修改用户内容。

## 决策

- 内置插件 `text-assist` 提供版本化能力 `text.assist.analyze@2`；第二版明确不承担普通输入法的通用词语联想。
- 资源状态能力保留 `text.assist.resources@2` 兼容入口，并新增 `text.assist.resources@3` 暴露外部 TXT 的关联状态与文件名；画布提示只消费新版本能力。
- 插件只通过 `content.catalog@2`、`content.read@1` 和 `content.createPlan@1` 的公开能力读取或规划文本节点，不读取文本节点私有命名空间。
- 可编辑语言资料只由普通文本节点 `纠错与补全规则` 承载。节点正文是事实源，`textAssistResource` 文档命名空间只保存规则节点的稳定绑定。
- 新画布通过一个无历史事务创建一个规则节点。产品尚未投入日常使用，因此旧画布中的通用、个人、画布词库及其旧停用记录在迁移时永久删除，不保留兼容数据。删除由 `entity.deletePlan@1` 的全部活动提供者规划，并与旧绑定清理组成一个原子事务，文本辅助插件不直接写文本节点、连线或群组命名空间。
- 规则节点属于系统放置资源，启动、打开画布或资源变化后由插件自动检查、修复和重编译。修复与补充命令保留为插件内部维护入口，但不再出现在命令面板或快捷键中心；用户不需要理解或手工执行维护步骤。
- 编辑器的即时确定性分析只提交光标附近 16 KiB 窗口；光标移动时重新定位窗口，因此不会在每次键入时扫描编辑器已装载的其他远处段落。插件仍拒绝超过 96 KiB 的第三方能力请求。
- 分析任务由内核任务调度器延迟、取消和清理。连续键入会取消旧任务，停用插件会释放尚未完成的任务。
- 纠错和补全共用一条候选管道：光标刚好位于已识别错字末尾时，纠错建议与节点标题候选在同一个弹窗中按“纠错优先”排序。
- 纠错和补全均为派生建议，不保存、不进入撤销历史，也不自动改正文。
- 两项能力可分别关闭。开关通过 `textAssist.toggleCorrection`、`textAssist.toggleCompletion` 指令执行，作为个人偏好保存，不进入书籍文件和撤销历史；节点标题链接保持独立可用。
- 用户接受建议后仍走现有 `content.applyDelta` 正文事务，保留修订检查、分块补丁、撤销重做、保存和索引失效逻辑。
- 标题引用使用精确标题匹配。为避免单字标题造成大量误链接，标题至少需要两个可见字符；重名节点先让用户选择。
- 标题引用继续以当前标题目录派生，不新增脆弱的正文内 ID 标记。文本节点改名时，`text-node` 按同一“精确、当前位置最长标题优先”规则分块查找已有引用，并把标题修改与所有命中的正文、格式修订放入同一个可撤销事务；目标节点自己的正文和被另一条更长标题占用的同前缀文字不替换。为保持事务与历史有界，单次改名最多同步 5,000 处引用，超过时整次改名失败而不做部分提交。复合操作使用 `content.renamePlan@1` 时也获得相同语义。
- 标题跳转通过 `selection.set` 和 `canvas.focusSelection` 两条公开指令完成，不直接操作画布或选择状态。
- 浏览器拼写检查只在文本辅助能力可用时启用。确定性引擎读取规则节点，支持固定词句纠错、忽略词、允许重复、易重复虚词、中英文标点映射、重复或冲突标点、重复文字、连续空格和中文标点前空格。
- 规则格式版本 3 增加 `[同音候选]`、`[形近候选]` 和 `[混淆候选]`。候选数据只参与派生建议，不能单独构成自动替换规则；同音异调默认关闭，减少无上下文误报。
- Echo-8 使用 pycorrector 的轻量同音字与形近字表，并保留 Apache-2.0 全文、固定上游提交和文件哈希。产品不打包 pycorrector Python 运行时、KenLM、8 MiB 词频表或姓名地名数据。原始表在构建时转换为独立 `Echo-8-text-assist-rules.txt`，纠错内容不嵌入 TypeScript、JavaScript 或便携 HTML；代码只保留解析、评分、候选和执行规则。
- HTTP 托管版在尚无本机副本时可以从同源公开路径读取该 TXT。直接双击 `file://` 便携版时，浏览器不允许网页静默读取同目录文件，因此核心在发起 `fetch` 前即返回“需要显式导入”，避免 CORS 控制台噪音。文本辅助插件在画布选择层显示醒目的“纠错规则尚未导入”项目；用户点击后通过浏览器文件选择器读取 TXT。
- 成功导入的完整字符串写入内核管理的独立 IndexedDB `personalAssets` 表，键由调用插件自动命名空间化。它不受普通偏好 256 KiB 上限约束，但继续执行 16 MiB、格式标记、文件名和非执行数据校验。`fresh-session` 只清空画布快照、日志、恢复点与正文块，不清除个人资源。下一次启动先读本机副本；命中后不访问旧文件句柄、不请求外部文件权限，也不显示未导入提示。用户再次运行“从 TXT 更新纠错规则”会覆盖本机副本并以无历史事务同步当前隐藏规则资源。
- IndexedDB 数据仍然受浏览器配置、站点来源和存储清理影响；移动便携 HTML、换浏览器或清理站点数据后可能需要重新导入。原 TXT 因而仍是可携带的来源文件，而不是被数据库取代的唯一备份。
- 普通词语输入和日常联想交给系统输入法。Echo-8 只补全画布节点标题；节点标题和规则中的忽略词还会保护专名内部文字，降低纠错误报。
- 资源格式是白名单数据语言，只接受已声明的段落、字段和赋值。节点内容不会作为 JavaScript、正则表达式、HTML 或命令执行。

## UI

- 纠错使用红色波浪下划线，点击后显示替换建议。
- 节点标题使用普通下划线，点击后聚焦对应节点。
- 补全在光标附近显示，支持鼠标、上下方向键、Enter、Tab 和 Escape。
- 编辑区格式栏提供只有图标的纠错、补全开关；纠错图标同时显示资源状态点：绿色为已加载，灰色为加载中，红色为未导入或正在沿用上一有效版本。鼠标提示会给出准确状态和固定纠错条数，因此状态不只依赖颜色表达。
- 所有候选均有可访问名称；插件停用后标记与候选自动消失，编辑器继续正常工作。
- 规则文件未关联时，画布左上方显示一个可点击的关联项目；关联成功后自动消失。它是插件声明到 `canvas.selection` 的运行状态视图，不是文本节点，不参与选择、保存、导出或撤销。

## 性能与边界

- 节点标题构造成目录级前缀树，目录没有变化时复用；规则节点不参与标题链接和普通正文分析，避免递归提示。
- 资源变化只使语言索引失效，不在每次普通正文键入时重建。资源读取使用 256 KiB 范围，单节点上限 16 MiB；解析、合并和索引编译优先进入内核管理的 Worker。
- 资源读取或解析发生致命错误时继续使用上一版有效模型并报告诊断；普通无效行会被忽略并记录行号，不拖垮编辑器。
- 单次最多生成 240 个标记和 8 个补全候选，避免可编辑 DOM 被大量 span 撑大。
- 当前纠错是离线、保守的确定性规则，不冒充完整语法、语义或事实校对。复杂句子和段落复核仍是以后可选的本地或远程模型能力，必须显式启用、展示来源并只返回建议，不能绕过正文事务。
- 默认规则包覆盖高频错字、固定搭配、成语、软件与办公术语、常见赘词、数量表达、重复虚词和中文标点。固定纠错在运行时编译为前缀树，正文窗口只做一次有界扫描，不随着规则数量线性反复扫描全文。
- 混淆匹配不会遍历任意词典。它只把高可信、等长固定纠错的正确结果和当前画布标题作为规范词，一次匹配最多允许替换一个字符，并受 2～12 字默认词长边界约束。不同候选仍使用前缀树和字符反向索引，取消请求可中止扫描。
- 新画布直接采用当前默认规则包。已有规则节点在插件启动或打开画布后，通过内部维护指令 `textAssist.mergeDefaultRules` 自动补齐缺失默认项；自动升级不进入撤销历史，按段落语义去重，也不覆盖用户已定义的同名纠错、候选组或开关。用户仍可打开规则正文或从 TXT 覆盖更新，但不再看到容易误解的“补充/修复”命令。

## 验证

- 纯算法测试覆盖错字、重复与冲突标点、最长标题、单字标题排除、标题补全、固定短语、重复虚词、忽略词、专名保护、允许重复、评分、非执行型规则、同音同调、形近候选和默认关闭的同音异调。
- 内核测试覆盖单一规则节点的无历史初始化、旧词库原子删除、普通文本节点承载、后台重建、能力调用和热停用后数据保留。
- 全量类型检查、架构边界测试、插件生命周期测试和单 HTML 构建作为交付门槛。
- 核心资源契约测试在模拟 `file://` 页面下断言资源能力要求显式关联且全局 `fetch` 调用次数为零；浏览器回归在规则 URL 不可用时验证画布关联项目可见、可选择 TXT 且关联后消失。
- 重命名合同测试覆盖普通精确引用、同前缀更长标题保护以及一次撤销同时恢复标题和正文引用。
