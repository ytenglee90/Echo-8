# ADR-0048：光标定位的文本辅助与分层 Escape 退出

## 问题

折叠光标在部分浏览器中会返回一个位于视口原点、宽高均为零的 `Range` 矩形。旧实现把这个空矩形当成有效结果，补全候选因此固定出现在编辑区左上角。

全局 Escape 监听原本运行在 DOM 捕获阶段。它会先于补全候选、AI `@` 候选、快捷键录入和缩放输入等局部控件执行，导致当前正在操作的临时对象无法优先取消。“打开其他书籍”的未保存确认也没有加入统一表面栈，核心无法把它识别为当前退出目标。

## 决策

- 文本辅助位置首先采用有效的浏览器光标矩形；零高度或无布局矩形一律视为无效。
- 无法直接测得折叠光标时，编辑器使用当前有界正文窗口内的文本偏移，通过相邻字符矩形推导光标边缘。它不插入测量 DOM、不读取完整长文，也不改变正文或选择。
- 候选位置继续限制在所属编辑器内；靠近边缘时只做边界翻转或夹取，不退回固定字数或固定左上角。
- Escape 使用三层顺序：局部临时对象、最近激活的受管 UI 表面、当前有效的全局 Escape 快捷键。
- Shell 的 Escape 协调改在冒泡阶段运行，并尊重局部控件的 `preventDefault`。Tab 焦点陷阱仍保留在捕获阶段。
- 局部候选关闭只改变派生 UI 状态，不进入文档历史；正文、选择和编辑器保持原状。
- 文件插件把待处理的书籍打开确认登记为 `overlay.floating` 受管表面，关闭指令为 `file.cancelPendingOpen`。Esc 通过 `system.ui.escape` 广播到该命令，不直接修改插件变量。
- 没有局部对象或可关闭表面时，`system.ui.escape` 执行当前快捷键中心解析后的 Escape 操作。默认仍为 `selection.clear`；如果用户清空或改绑该快捷键，核心不硬编码选择插件。
- 中文输入法组合期间的 Escape 仍由输入法拥有，不进入应用退出链。

## 兼容性

不修改 `.echo8` 文件格式、正文模型或历史格式。新增的文件取消指令只操作瞬时打开意图。文本辅助仍使用 `text.assist.analyze@2`，没有新增跨插件数据依赖。

## 验证

- 浏览器测试在多行正文末尾触发补全，验证候选位于真实光标所在行而不是编辑区左上角。
- 浏览器测试验证第一次 Esc 只关闭补全候选，编辑器和光标仍保持活动。
- 浏览器与内核测试验证未保存书籍的打开意图可由 Esc 取消。
- 浏览器测试验证没有活动表面时，Esc 仍执行有效的“取消选择”快捷键。
