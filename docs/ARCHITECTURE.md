# Echo-8 Architecture

## Runtime path

Every durable user operation follows one path:

```text
input adapter -> typed command -> command router -> permission/conflict validation
-> transaction manager -> single store write boundary -> global history/persistence
-> committed events -> render/index/statistics/diagnostics
```

Public command names, payloads and results are joined by the declaration-merged registry in `src/protocols/commands.ts`. `ViewClient` and scoped plugin command dispatch infer from that registry; callers cannot declare their own result type for a registered command. Runtime schema, manifest and permission validation remain mandatory because static types do not validate imported files or third-party input. See ADR-0062.

Pointer movement, camera motion, lasso previews, editor previews, and panel resizing use the ephemeral signal channel. They are still broadcast messages, but they are coalesced and never enter document history. Interaction end commits one durable command when content changed.

Formal commands use one global serial queue. A command handler must never enqueue another formal command and then wait for that queued work, because the child cannot start before the parent finishes. The scoped plugin context therefore exposes two explicit composition paths: `commands.invoke` expands a declared child command inside the current serialized turn, while `commands.defer` queues a declared follow-up after that turn and deliberately returns no awaitable promise. Ordinary nested `dispatch` fails immediately instead of hanging. Both paths retain correlation, causation and propagation depth across asynchronous handler work. See ADR-0035.

Committed events are facts, not a second transaction phase. Delivery is ordered per receiving plugin, but each plugin has an independent observer tail; a slow index, statistics or autosave observer cannot hold the formal command queue or delay another plugin's observer. Event failures are isolated and recorded in diagnostics.

## Dependency boundary

- `src/core` is headless coordination and mandatory services. It contains no text-node, canvas, editor, group, connection, AI, or palette behavior.
- `src/shell` owns layout and renders governed UI slots. It contains no feature data writes.
- Embedded feature surfaces use governed slots too. The canvas owns only camera/input infrastructure and hosts `canvas.entities` plus `canvas.empty`; the text-node plugin contributes its renderer and empty-state action there without a feature-to-feature implementation import. Likewise, `ai.settings` is hosted inside the AI assistant while its content remains owned, permission-checked, and hot-removable by the AI provider plugin; it is not a right-rail surface.
- Live AI transcripts are plugin-owned chunk records, not automatically created canvas nodes. The first save publishes one source node and one index node; later manual or interval-based saves update those same nodes through content-plan capabilities and the global transaction pipeline.
- `src/plugins/<feature>` owns one feature and imports only core contracts or its own files. Feature plugins never import another feature plugin.
- `src/protocols` contains public message and capability data shapes. It contains no implementation and prevents plugins from importing one another just to share a type.
- Stateful feature plugins split headless behavior into `model.ts`; `plugin.ts` is only the composition point that attaches optional React views.
- `src/plugins/index.ts` is the composition root and is the only place that knows the complete built-in plugin list.
- Cross-plugin access uses versioned semantic capabilities such as `content.summaries@1`, `content.read@1` and `content.renamePlan@1`. A memory rename, for example, obtains text-owned title patches instead of writing the text-node namespace from the AI plugin.
- A plugin boundary represents independently stoppable behavior, state ownership and a public protocol—not every internal component. Large views may be decomposed into private modules while remaining one plugin when those modules cannot be meaningfully started or stopped on their own.

## State domains

- `document`: authoritative, saved, globally undoable content.
- `workspace`: device/personal layout state, saved separately from document undo.
- `ephemeral`: hover, focus, drag, pan, temporary editor preview.
- `derived`: rebuildable previews, counts, indexes, visibility and geometry.

Plugins receive a scoped context. They can read only declared namespaces and can write only by returning standard transaction patches from registered commands. A plugin must separately declare commands and queries it consumes plus signals it emits or observes. The router rejects undeclared use before delivery.

Omitting a command or query payload validator is an explicit payload-free declaration: only `undefined` is accepted. Any message accepting data must provide a runtime schema even when TypeScript already describes the payload.

Each document/workspace namespace has exactly one schema owner. Ordinary transactions may patch only the command owner's namespaces. Cross-feature operations, such as deleting a selected node and all attached connections, ask every `entity.deletePlan@1` provider for owner-labelled standard patches and commit the combined plans once.

Theme tokens are an exception only in location, not in discipline: the mandatory UI runtime owns theme registration, activation and cleanup because it governs every UI slot. Feature plugins may register complete semantic theme definitions through their scoped UI context, but cannot mutate DOM styles or another view directly. Document appearance remains feature-owned data.

The shell derives local ink, muted, faint, border, control and hover values from semantic chrome backgrounds before rendering governed slots. Every `right.primary`, floating-panel, command-palette and immersive-panel-overlay contribution consumes the panel-derived set; modal dialogs, task notices and inline suggestion surfaces opt into the same scope at their surface root. Labels, inputs, placeholders, shortcuts, controls and state messages therefore follow the actual panel luminance instead of assuming the theme's general text color. Document paper and node content remain outside this chrome scope.

The UI runtime also owns the action catalog and the only global keyboard registry. Plugins declare searchable actions and default shortcuts through scoped contributions. The command-palette plugin reads the catalog and broadcasts `system.action.execute`; the core resolves the still-active contribution and queues its command for the next serialized dispatch turn. Personal shortcut overrides are proposed by the shortcut-center plugin, atomically conflict-checked by the UI runtime, stored in workspace state and removed from the active registry when that plugin stops.

The mandatory UI surface arbiter owns cross-slot visibility conflicts. When a committed feature operation reveals `right.editor`, it publishes the generic `system.ui.surface.revealed` fact. The arbiter finds the active conflicting `right.primary` surface and queues that owner's declared close command through the router. Editors and panels never import, inspect or mutate one another, and a future right-side panel participates by registering its governed surface and public close command rather than adding another editor-specific listener.

Escape arbitration is layered rather than captured globally before controls can react. A focused local transient control may dismiss its own completion, mention or input mode first; otherwise `system.ui.escape` closes the most recently activated governed surface. If neither exists, the UI runtime resolves the current effective Escape shortcut (normally selection clearing), including user overrides. Pending project-open confirmation is a governed floating surface and cancels through its file-owned command. IME composition retains ownership of Escape throughout composition. See ADR-0048.

Large feature views are split only inside their owning plugin. The editor dock delegates its format bar, metrics and resize handles to editor-owned components; the AI panel delegates memory and Prompt management views to AI-owned components. These components keep the same scoped `ViewClient`, dispatch the same public commands and never become shell logic or separate data owners.

State invalidation is tiered: document revision, workspace revision, plugin-private namespace revision, capability-registry revision, command-registry revision and typed feature invalidations are distinct. `content.catalog@2` publishes bounded deltas, and its invalidation distinguishes geometry changes from body-only changes. A selection change or one typed character therefore does not invalidate every text preview, connection bound or group bound.

Catalog consumers request every active `content.catalog@2` provider. A single provider retains its incremental `sinceVersion` path; multiple providers supply full snapshots that are deterministically merged by stable entity ID, so adding another content owner never silently replaces the first provider.

The scoped store also exposes prefix/range reads plus a bounded namespace change journal. Plugins that own large keyspaces can refresh only changed keys and clone only the requested range; a missing journal window explicitly requests a full rebuild. The text-node catalog uses this to maintain its title allocator and node count without rescanning every node during batch creation.

## Plugin lifecycle

Plugin activation validates manifest declarations, dependencies and required capabilities. Starting registers commands, queries, event listeners, signals, capabilities, UI contributions, shortcuts and tasks through the resource registry. Optional controls observe the command registry and disable immediately when their provider disappears; a dispatch racing with hot-stop still fails closed at the router.

Automatic activation is dependency ordered rather than registration ordered. The plugin manager advances only manifests whose required plugins are active and whose required capabilities are already provided. Explicit cycles are rejected with the cycle path and missing or disabled providers are reported without partially starting the consumer. Optional dependencies never become mandatory graph edges. See ADR-0032.

Stopping first suspends the owner's capability admission, cooperatively aborts capability requests that received an `AbortSignal`, and waits for every already-admitted provider promise to settle. It then cancels owned tasks and workers, invokes plugin cleanup, and forcibly releases every tracked resource. Plugin-owned document data remains in the store. Restarting reopens capability admission and rebuilds runtime resources against the retained data. See ADR-0060.

Resources without a richer facade use `context.resources`: timer, listener, file and other leases are registered under the plugin owner and are forcibly disposed during pause, stop, uninstall or failed startup. Global interaction sessions are similarly owner-scoped; an interaction can end only when owner, optional mode and optional session token match the active gesture.

## Long background-task feedback

Heavy work remains owned by the mandatory task scheduler. Task declarations include a stable category plus an optional user-readable label and notice delay. The shipped UI observes only the scheduler snapshot: a task that is still queued, running, paused or retrying after 1.2 seconds receives one unified non-blocking progress notice below the toolbar. Short work never flashes a notice, and settled or owner-cancelled work disappears through scheduler cleanup. Feature plugins do not mount independent global loading overlays.

CPU-heavy derived computation additionally goes through the kernel-owned `WorkerService`. Plugins declare exact namespaced job IDs and the `workers.run` permission, then submit bounded immutable payloads through `context.workers`. The scheduler still owns the task lifecycle; the worker never reads the store, writes history or invokes another plugin. Stopping a plugin cancels its worker jobs through normal resource ownership. See ADR-0029.

The hosted Vite composition creates its module Worker from a static `new URL(...)` at the application composition root, so Vite transforms it as a worker environment. A narrowly scoped development-server bridge supplies only Vite's `injectQuery` helper when the local-semantic Worker module imports a governed Blob module; it prevents Vite 8 from loading the page-only HMR client in `WorkerGlobalScope` without changing page HMR or production output. Development, ordinary E2E, performance and cross-browser gates all exercise this real path; no test configuration disables the background worker as a shortcut.

## Persistence and file boundary

Autosave is a mandatory core service. Committed standard patches first append to an IndexedDB recovery journal; adjacent records from the same explicit edit session are compacted before admission, and a complete store/history checkpoint is created only when the configured checkpoint interval has elapsed or an explicit save/recovery operation requires one. Automatic checkpoints enter the unified low-priority task queue, while journal and checkpoint writes pass through one serial persistence queue. Store records and history patches are captured as a stable point-in-time view in short slices. Immutable正文 chunks are reference-captured by the private persistence path, externalized before worker transfer and cloned only at the durable IndexedDB boundary; ordinary snapshot APIs still return independent deep copies. The persistence service supports both restoring and discarding a previous session. The hosted composition selects `restore-session` so it can retain offline work and cloud upload queues across browser restarts; the portable single-HTML composition selects `fresh-session`, starts blank and keeps `.echo8` as its cross-session document boundary.

Cross-device persistence is an optional `cloud-sync` plugin over the same transaction and document-replacement boundaries. Both hosted and portable compositions register it together with `book-library`, which occupies a governed welcome slot, lists cloud projects without acquiring a lease, and requires an explicit selection before opening one. The portable `file://` runtime still has no account backend: cloud sync registers its visible surfaces but makes no control-plane request, explains that HTTP(S) hosting is required, and keeps `.echo8` as the cross-session document boundary. An HTTP(S) deployment uses the same-origin `/api/cloud/*` control plane. Switching an active cloud book first flushes its pending records and releases its lease. A newly created canvas keeps its current document in memory and immediately creates a timestamped cloud project when a ready personal installation is available; without one it stays silent until a later automatic checkpoint needs the ordinary local fallback. Ordinary Save remains an explicit fallback and Save As remains an explicit local `.echo8` copy. The import/export owner makes that decision from the core document-replacement origin: an opened local file, recovery, external replacement or explicitly disconnected cloud book is never implicitly converted into a cloud project. Project-name edits stay ephemeral in the React surface until a typed cloud command sends an authenticated metadata-only `PATCH` to the user's data Worker; renaming does not enter document history or rewrite canvas content. Cloud-project deletion is likewise cloud-sync-owned: the library and sync panel request one governed confirmation flow from accessible icon buttons. Deleting the active book first creates a local recovery checkpoint, then clears its cloud binding and upload queue while retaining the current document as an unconnected canvas. The library brand, browser favicon, loading surface and toolbar cloud status all use the canonical wide `public/favicon.svg`; the application preserves its intrinsic rectangular proportion instead of drawing or clipping it inside square containers, and the portable builder embeds that same source as data URLs rather than issuing a `file://` request. The SVG outer canvas is transparent rather than white. Its logo body is one solid rectangular silhouette with paired transparent channels and offset diagonal cut-outs; the body, not the channels, is the mark. Runtime brand surfaces use that silhouette as a monochrome mask filled with the semantic foreground derived from their actual background, so theme inversion or recoloring changes only the body while every cut-out continues to reveal the surrounding surface. Exact cloud state remains in the button's accessible label and hover title. The toolbar keeps the enlarged mark itself neutral with no status backdrop: full contrast means synchronized, unavailable states use grayscale and reduced opacity, and active work uses bounded breathing motion, all without a separate status dot or colored brand outline. The book library likewise derives the active row from semantic ink and surface tokens, making the current book a dark reverse row in the light theme and a light reverse row in the dark theme; title rename remains a compact title-only target while the free row surface continues to open the book. The owner-side control Worker stores encrypted Cloudflare OAuth grants and installation metadata in a control D1 database, but no canvas body. A provisioned user-side Worker binds that user's D1 resource. The browser receives only a ten-minute installation-scoped data token, externalizes immutable text chunks from commit JSON and sends ordered committed transaction records directly to the user Worker. D1-first installations store chunks in bounded rows and structural checkpoints in byte-verified UTF-8 parts; the data Worker keeps an explicit optional R2 boundary for a later account upgrade. The control plane records a separate monotonic data-Worker release version. When it lags the application target, the plugin offers an explicit typed upgrade command that reruns idempotent schema work and republishes the same Worker only after account ownership is revalidated; the original ready metadata remains intact on failure. One project lease permits one editing device; other devices open read-only and require explicit takeover. Head mismatches retain the local queue and require a recovery point before remote replacement. Shared cloud checkpoints exclude local undo/redo history. See ADR-0067, ADR-0068, ADR-0069, ADR-0070, ADR-0073, ADR-0075, ADR-0076 and ADR-0077.

Local complete checkpoints externalize immutable `textContentChunk` values into a dedicated IndexedDB store. Latest snapshots, history references and recovery points share chunks by ID; only new IDs are written, and chunk garbage collection retains the union referenced by the latest checkpoint and remaining recovery points. Hydration restores the ordinary store and history contract before replay. This representation is local-only and does not change the portable `.echo8` format. See ADR-0030.

Portable `.echo8` files are owned by the import/export plugin, but document replacement is a core-only operation. The plugin parses and verifies the file in a cancellable background task under independent compressed-byte, expanded-byte, logical-entry, fragment-count and entry-count ceilings, then dispatches `system.document.replace`. Before replacement, core stages declared plugin data migrations over cloned owner namespaces; failure leaves the open document untouched, while success updates descriptors and retires legacy history that could reintroduce the previous schema. The transaction manager then performs one exclusive document replacement boundary, resets imported history, publishes `document.replaced`, and forces a new local checkpoint. Personal workspace state is excluded from portable files; file-bound selection and editor panes reset through follow-up commands after the committed replacement event. See ADR-0060.

When the browser provides a writable file handle, `.echo8` serialization is written as bounded NDJSON chunks directly to that handle. Manual file save reads one immutable project source snapshot and does not start and await a second scheduler-owned checkpoint from inside its file task; local recovery points remain a separate explicit/autosave operation. This prevents a large checkpoint cost from forming a scheduler dependency cycle with the save task or starving active AI streams. The download fallback still uses a `Blob` because it has no streaming filesystem target. Both paths share the same generator and checksum rules, so streaming is a memory optimization rather than a second file format.

## Current vertical slices

The text-node plugin owns small content metadata, independent 64 KiB content-chunk records and whole-document typography records. Its internal `content-storage.ts` module is the single implementation boundary for chunk creation, range reads and revision-checked delta/replacement plans, while `formatting-storage.ts` owns formatting validation, mark transformation and move planning. The plugin entry remains responsible for public commands, capabilities and lifecycle only. It exposes range-based read, storage diagnostics and revisioned formatting capabilities. Text edits replace only intersecting chunks instead of cloning or joining the entire document. Legacy inline chunk arrays migrate through a normal non-history broadcast transaction. Editor deltas carry the source revision and a focus-scoped typing session, so stale views are rejected and continuous input merges without crossing focus or formatting boundaries. Title references remain derived exact-title links, but a title rename now range-scans the affected canvas content with the same longest-title rule and commits the renamed title plus bounded linked正文 replacements and formatting transforms as one transaction; `content.renamePlan@1` shares that behavior. A text entity may be shown as a正文-preview card or as a transparent, border-only text box. The text owner stores the presentation plus independent card and text-box sizes; one typed transaction switches shape and restores that shape's remembered geometry without deleting the hidden正文. Text boxes retain one stable, size-wrapped title-only rendering across canvas zoom levels, edit their title inline on double click and expose only left/right connection ports. Their title uses an 18 px font and the single outer frame uses a stable 3 px stroke in both ordinary and selected states. The inline title control is transparent and has no independent border, outline or shadow, so editing keeps a single visible frame supplied by the selected text box. Cards place their conversion control beside the palette control in the title bar; the centrally registered, initially unbound “文本框与文字节点相互转换” shortcut toggles every selected text node in one transaction and is paired with its public action in the shortcut center. Canvas cards render bounded, shadow-free plain-text summaries with their default preview ink; selected nodes use one adaptive border rather than a second nested outline, while duplicate-origin and connection-target states retain their distinct transient indicators. Editor document defaults, range color marks and color-scrub previews remain editor presentation and never recolor the canvas summary. See ADR-0061 and ADR-0066.

The editor plugin keeps at most three distinct panes in workspace state. A fourth node replaces the least recently active pane deterministically. Dock resize previews are ephemeral and release commits one personal-layout command. Above the ordinary editor threshold, each pane mounts only a 256 KiB range and changes the range through `editor.setWindow`; reaching the visible range boundary requests the adjacent range without mounting a separate pagination toolbar, and edits convert local selection offsets to global document offsets. The editable range is painted before any uncached whole-document metric scan starts. Until that cancellable scan returns, the footer explicitly says `统计中…`; the revision-matched result then replaces it with the same exact non-whitespace grapheme count used by navigation. Stale or in-flight-edit metrics cannot overwrite a newer local buffer. The UI runtime derives a black/white `--editor-paper-ink` from the active writing-paper background; ordinary default正文 and the caret consume that semantic ink, while explicit document/range colors remain owned formatting. The editor owns runtime-session aggregate writing metrics with a 60-second idle timeout; IME commits count once, paste and same-document text moves are excluded from typing speed, and selection count remains ephemeral. During IME composition, browser-owned marked text stays local to the focused control: no body/title preview, correction request, annotation autosave, AI draft persistence or local-history entry is published until `compositionend` provides the final text. Metrics use a separate workspace namespace so activity updates do not invalidate pane layout. Whole-document, paragraph and selection formatting share `content.formatting@2`. Partial marks use biased text anchors that follow insertion and deletion, survive copy/paste and enter the same global history as content edits rather than storing fragile raw offsets. Dragging an editor selection within the same正文 dispatches one `content.moveRange` command; the text owner moves chunked content, formatting marks and public annotation anchors in one undoable transaction, while external drops remain copy operations. Undo, redo and document replacement invalidate the pane's cached authority; a delayed browser input delta is rebased onto the current authoritative正文 before dispatch rather than overwriting the history result. Color scrubbing over a selection or paragraph uses a revision-bound ephemeral mark and never changes the whole-document default before commit.

Immersive writing is injected into the shell-owned modal layer and requests native browser fullscreen only during the initiating gesture. It renders only the writing surface and exit control; the dock title, formatting controls and bottom metrics/status bar remain absent. The shell handles ordinary Escape through `system.ui.escape` and also observes `fullscreenchange`: if the browser consumes Escape while dismissing native fullscreen, the still-active immersive surface is closed through the same governed command path. A shared UI-runtime clock drives time displays in the ordinary editor, so feature views do not create unmanaged global timers.

Text-range annotations keep durable character anchors. A point belongs to the character on its left: insertion at the exact anchor stays to its right, insertion before it shifts it, and deletion or same-document movement carries points in `(start, end]`. Content delta and move plans transform those anchors in the same transaction as正文 and formatting. The editable DOM may update before that transaction commits, so editor markers must not remeasure against new DOM text paired with old durable offsets; they remeasure only after the committed annotation invalidation/formatting revision. Copy/cut writes bounded, versioned annotation metadata beside `text/plain`; a matching paste or external editor drop asks `content.annotationClonePlan@1` for owner-labelled patches and commits cloned annotations with正文 in one history entry. This prevents every marker from appearing one character to the left during an input frame and preserves annotations across native clipboard workflows. Canvas/editor markers and the annotation popup use flat borders without drop shadows. Canvas markers convert their world anchor to a screen-layer position on every camera preview. Their 25 px frame and icon use half-strength compensation below 100% zoom: screen size follows the square root of camera zoom, reaching about 16 px at 40%, while 100% and above retain the 25 px cap. The editor retains its ephemeral selection and scroll position across derived DOM projection rebuilds. The immersive editor exposes the same governed annotation command; its nested `editor.immersive.overlay` slot renders the popup inside the existing immersive surface, and closing it restores the prior caret and viewport without unmounting the editor or exiting native fullscreen. See ADR-0063.

Selection is a real workspace plugin with replace/add/remove/toggle modes, lasso selection, spatially scoped select-all, focus and deletion. Nodes, connections and groups contribute through the same generic entity catalog, so selection does not infer types from identifiers. Reapplying the same ordered selection is an explicit no-op: it writes no workspace patch and publishes no `selection.changed` event, preventing repeated clicks from restarting expensive dependent statistics. A container may require complete lasso containment and expose contained IDs; the selection owner removes duplicate direct member hits rather than changing them into a container by guesswork. Select All asks optional pointer and scope capabilities, keeping group geometry out of the selection implementation. Node and group dragging use coalesced preview signals and commit all moved nodes as one transaction on pointer release. The independently stoppable smart-layout plugin builds derived spatial references from public selection catalogs and provides the bounded synchronous `layout.snap@1` and `layout.resizeSnap@1` interaction capabilities. Text-node drags align against nodes and group frames; group drags treat every stationary group as one outer box. Node bottom-right resizing compares only frame edges, broadcasts transient guides and snapped size previews, then commits one existing resize command on release. Edge, center and equal-spacing guides remain transient and use a fixed screen-pixel threshold converted to world units. The same plugin owns `node.arrangeSelectedGrid`, while text-node supplies the owner-labelled `layout.gridPlan@1` patch plan; automatic layout therefore disappears cleanly on plugin stop and still commits as one global transaction. Canvas cards, connections and group frames are queried through rebuildable spatial hash indexes and then exact-culled against a shared viewport protocol; only completed camera changes persist.

Connections are a separate document plugin. The canvas sees only `connections.available@1`, broadcasts endpoint intent and sends `connection.create`; the connection plugin owns validation, storage and adaptive SVG rendering. Ordinary connections retain automatic left/right endpoint resolution as nodes move. An explicit `title` endpoint, created only from the title-bar port, pins both ends immediately before the title dot and routes the curve outside the cards' left edges; it survives movement, clipboard transfer, save/open and history replay. All cubic curves use enlarged horizontal start and end control handles. Ordinary control directions come from endpoint semantics rather than edge-coordinate ordering, so a right port always exits right and a target left port always enters right even when the node rectangles overlap horizontally. Every committed or draft visible path stops its curve shaft at the arrow base and closes a solid triangle to the target endpoint inside the same SVG `d`, aligned to the final tangent. There is no overlaid marker, overlap tail or arrow/curve seam; normal, selected and hovered arrows inherit the same fill and stroke as their curve. At 100% zoom, arrows are approximately 14×14 px and visible strokes are 1.5 px. Below 100%, visible curve strokes, arrow geometry and the complete label/editor frame use one shared half-strength compensation whose screen ratio is the square root of camera zoom, so they become about 63% of the base size at 40% instead of dominating the overview; at and above 100% they retain the base screen size. Automatic and global inherited lines use adaptive selection color without changing compensated thickness. An object-level custom line instead keeps the exact picker RGB value in ordinary, hovered and selected states, while hover, keyboard focus and selection share one bounded extra-width cue and never add a shadow. Interactive SVG paint order is stable within two partitions—ordinary connections first and selected connections last—so selection brings a curve and its hit area above crossing peers without changing document order; dense mode retains its selected overlay after the batch path. A connection owns one bounded optional label, its reference width/height and one shared revision. Double-clicking its hit geometry or existing label opens a local multiline editor at the sampled arc-length midpoint; ordinary Enter or blank-canvas blur commits through `connection.setLabel`, Ctrl/⌘+Enter inserts a newline, and an empty value removes the label. Label text wraps to the stored frame and uses 12 px type with a 1 px frame at the 100% reference size. Its lower-right resize handle publishes coalesced `connection.label.resize.preview` state while dragging and dispatches one revision-checked `connection.resizeLabel` command on release, so the committed size is globally undoable without recording intermediate frames. Labels follow the world-space curve while their text and border use the same ordinary or selection color as the corresponding normal, hovered or selected curve. Text and size survive clipboard transfer and project save/open without moving editor state into the document. Ordinary visible sets keep one accessible curve-only hit path per connection. Its wide hit stroke alone remains non-scaling, fully transparent and shadow-free so the reduced overview visual is still easy to select; the layer forwards non-passive wheel input through `canvas.wheel.requested` so hovering a connection never blocks camera zoom. Above 600 visible edges, the view collapses curves and their arrow subpaths into one compound SVG path and performs pointer selection with spatial candidates plus curve-distance hit testing; selected and hovered edges remain separate adaptive overlays. Only labeled edges add midpoint label DOM, so unlabeled dense sets keep the compound-path DOM bound. The actual canvas background, including color-picker preview, produces a minimum-3:1 automatic/global ordinary stroke and a stronger black/white selection stroke shared by inherited-color connections, arrowheads, labels, node/group selection, snap guides and the lasso frame. User-selected object colors are deliberate content and remain exact. This derived view state never changes document records, commands or history. The camera clamps all preview, command, focus and stored-workspace entry paths to 40%–240%. The shell fixes the visual stack as group background, connection layer, node world and selection overlay. Within the node world, selected cards receive the highest node-local stacking level without changing document order or history. Node deletion obtains plans from both text and connection providers, so one undo restores the node, its body and every attached connection together.

Connection appearance remains connection-owned durable document state. The global-color panel discovers the single `connection-line` target through `appearance.read@1` and commits its revision-checked `connectionAppearance` patch through `appearance.updatePlan@1`; the palette never reads the private namespace. A selected connection additionally exposes independently selectable `line`, `label-background` and `label-text` parts under the same durable connection ID. Groups are flat document containers rendered through the governed `canvas.groups` slot. Their titleless bounds are derived from member geometry with uniform padding; legacy multiline title and title-style fields remain group-owned durable compatibility data but are not rendered and do not affect geometry. Group dragging broadcasts the same coalesced node-position preview used by ordinary dragging and commits one `node.moveMany` command on release.

The internal clipboard is a workspace plugin. Serialization and instantiation are multi-provider capabilities: text nodes, connections and groups contribute opaque versioned fragments and owner-labelled paste patches. New IDs are allocated before any provider builds references, allowing connections and group memberships to target the pasted nodes without importing another plugin.

Search/replace is a workspace and task-oriented plugin. It owns no正文 data: background searches call `content.search@1`, while durable replacement obtains a revision-checked `content.replacePlan@1` and submits those patches once. Search results remain transient and are discarded after replacement.

Statistics are rebuildable derived state. The statistics plugin schedules cancellable low-priority scans through `content.statistics@1`, combines optional module contributions and broadcasts the latest snapshot to the status bar. The toolbar, visible canvas node headers, editor total and editor selection therefore consume the same revisioned character metric and integer formatting. The segmentation and whitespace semantics behind those displays have one implementation in `src/services/text-metrics.ts`, including a streaming counter that preserves grapheme boundaries across text chunks. Feature plugins consume it rather than creating their own `Intl.Segmenter` character definitions. See ADR-0062 and ADR-0074.

The palette plugin owns personal theme choice, panel state, editor background, annotation color and the global group-background source color. It asks optional `appearance.read@1` providers for public targets and optional `appearance.updatePlan@1` providers for revision-checked, owner-labelled patches. Canvas background remains canvas-owned; node title and body text colors remain text-owned. The icon-only selection palette sits in its own toolbar group immediately before clipboard and opens beside the selected entity with `P`; the older node-local title picker button is not rendered. Selection-scoped reads can address a connection paint part while keeping one durable object ID, and mixed module kinds share one preview color before all owner plans enter one global-history transaction. Optional group and annotation record colors inherit their workspace defaults, so a local commit changes only selected records and leaves global preferences untouched. `appearance.colors@1` rebuilds the picker records from every active owner, including range text and connection-label colors. The Reset action composes `appearance.resetPlan@1` document patches as one undoable command, then separately restores palette-owned personal defaults outside document history. Color scrubbing uses the coalesced `appearance.color.preview` signal. The A 明调, B 暗调 and C 护眼 presets are implementation-owned combinations over the same existing canvas and workspace operations; there is no new stored preset ID, and manual changes naturally become a custom combination. Disabling the palette settles an active picker as cancelled, clears its preview, removes its themes, panel, shortcut and listeners, restores the core fallback theme, and preserves both document colors and personal preferences. See ADR-0078 and ADR-0079.

Groups are flat, titleless derived frames whose durable records contain membership and retained legacy-title metadata. The container and every member node remain independent direct selection items. Selecting a group expands members only through `selection.resolve@1` for whole-container operations; selecting every member never rewrites or serializes them as the group. A lasso must fully contain the group frame to select the container, while a partial lasso selects only reached nodes. Pointer-scoped Select All selects the members of the smallest containing group; canvas-wide Select All stores groups plus ungrouped entities and omits duplicate direct member IDs.

The import/export plugin supplies project save/open, current-node TXT, whole-canvas TXT and recovery UI. Project records are newline-delimited, split at bounded fragment sizes, and protected by a CRC32 interruption/corruption check. Unknown document namespaces and their retained plugin descriptors survive open and resave. Recovery asks the core for a read-only comparison preview before the separate destructive confirmation. Command-palette and panel opening starts with `file.requestOpenProject`; dropping `.echo8` (or the forgiving `.eco8` read alias) broadcasts `file.openProject`, and the canvas never parses project bytes. A dirty document enters one shared transient save/discard arbiter before a chooser or dropped file may replace it. The book-library welcome surface instead uses `file.openProjectFromLibrary`: choosing a book there is already an explicit switch, so it skips the duplicate prompt while core document replacement still creates a full recovery point. Saving must finish first in the ordinary canvas flow; discarding issues a short-lived one-use authorization. After asynchronous Save As, a picker flow exposes a second explicit chooser button because browser user activation cannot safely be reused. None of this transient state enters history or persistence. TXT bodies are range-read through `content.read@1`; the file plugin never reads text storage directly.

Core checkpoint and journal status is described as a browser recovery copy, never as a saved book file. Portable startup clears it; hosted startup restores it. Only the import/export plugin, which owns the actual retained destination handle, may report that a `.echo8` book file was saved or automatically overwritten, while the cloud plugin separately reports a completed remote sync.

Large personal text resources and bounded encoded device-local derived caches use the kernel-owned IndexedDB `personalAssets` store rather than document/workspace namespaces or the 256 KiB preference channel. The kernel namespaces keys by requesting plugin and enforces a 16 MiB text ceiling. Fresh-session document cleanup deliberately leaves this store intact. The text-assist plugin uses it for an imported correction-rule TXT, while the local semantic provider uses a smaller 15 MiB envelope for a versioned vector-cache encoding that contains no source text. This device-local state is never included in `.echo8`, history, recovery snapshots or project checkpoints.

The diagnostic center depends only on mandatory core queries. Its `system.runtime` snapshot contains counts, revisions, health, queues and sanitized errors; it never includes namespace values or node正文. It refreshes through the shared UI clock, so it neither polls plugin internals nor owns an unmanaged timer. The panel itself remains hot-switchable and a failed feature plugin cannot take away the core diagnostic query.

AI is split into independent concerns. The assistant owns conversations, retrieval orchestration, provenance and reviewable proposals; the model-provider plugin owns named platform profiles, the active Chat Completions-compatible network connection and per-profile in-memory session keys; the rebuildable search-index plugin provides chunked BM25 `context.search@3` retrieval and status diagnostics. The independently stoppable semantic-provider plugin owns remote embedding profiles, explicit remote-content consent, a cancellable bounded overview-index task and an in-memory vector cache, and provides `context.semanticSearch@1`. Chat generation uses the `network.ai.generate` boundary while embeddings use the separate `network.ai.embed` boundary. The assistant rank-fuses semantic results with BM25 without depending on either provider's implementation, and semantic failure returns no contribution instead of discarding BM25 results. Saved profiles contain only personal connection metadata and consent; keys and vectors never enter document state, workspace state, history, autosave, recovery data or project files. The assistant depends on generic `context.*` capabilities, so future tables, image descriptions, web clippings and transcripts can participate without importing the text-node implementation.

The local lexical provider keeps source text range-based. Its managed worker produces bounded per-window signatures and a compressed inverted candidate index whose posting lists use delta-varint encoding. Ordinary queries intersect postings before reading text; oversized or high-entropy chunks and single-character queries retain Bloom/full-candidate fallbacks, and every hit is still verified against current original text. See ADR-0041.

The local semantic provider runs the fixed quantized BGE model through ONNX WASM in the same managed-worker boundary and contributes `context.semanticSearch@1` beside BM25. Its completed embeddings may be retained as a bounded, versioned device-local `personalAssets` record containing only source identities, revisions, block fingerprints, ranges and vectors—never titles or正文 excerpts. A restart still range-reads current blocks and reuses a retained vector only after the fingerprint matches; incompatible, corrupt or oversized cache data is disposable and rebuildable. Encoding and decoding remain worker jobs, while the cache stays outside document state, history, recovery and portable files. See ADR-0056.

Large conversation archives are prepared outside the formal command queue. A cancellable task range-reads the one session's indexed transcript chunks, validates the transcript and target revisions, and builds owner-labelled patches. The short commit command accepts only a trusted in-memory preparation ID, revalidates every precondition and applies the prepared patches once. Other canvas commands therefore remain responsive while a long archive is assembled.

AI transport enforces an 8 MiB raw response ceiling, bounded SSE lines and bounded combined events before parsing. Declared oversized bodies are rejected before reading; streaming readers are cancelled on limit, abort or parse failure. These transport ceilings are separate from the smaller product output and context budgets.

Visible AI answer/reasoning deltas are an ephemeral projection coalesced to at most one React update per visual frame. The current card renders escaped plain text, so it does not repeatedly parse a Markdown tree while streaming; completion or unmount cancels any queued frame before the authoritative transcript replaces the projection. The latest send also keeps a 24-hour runtime-only follow-up action: failures expose a retry icon, successful answers expose a generate-again icon, and both retain visible tooltips/accessibility names before dispatching one typed command. A retry reuses the original prepared prompt/evidence without duplicating the question; a repeat preserves the previous answer and records the user's short control turn before producing an alternative. Transcript and evidence revisions are revalidated before either task starts. See ADR-0020.

Each AI assistant owns an independent workspace-only native-web-search switch. Context preparation freezes the switch into the pending request. The provider advertises whether the selected connection has a verified native adapter and injects only that platform's documented request field; unsupported connections fail before network transmission instead of pretending to browse. Model IDs remain free-form strings with UI suggestions rather than an application whitelist. See ADR-0037.

Remote semantic source revisions do not automatically invalidate every cached vector. Ordinary sources are range-read and indexed as complete paragraph-aware blocks; each block has a fingerprint over the exact title-and-text embedding input, so unchanged blocks reuse vectors and only changed blocks are sent to the configured provider. Exceptional sources above the complete-coverage ceiling use up to 128 deterministic paragraph probes spread across the document, and the UI reports that partial coverage explicitly. Identical fingerprints share one embedding request without merging their source ranges. See ADR-0031 and ADR-0042.

AI context preparation resolves the model profile selected by that assistant window and derives a conservative evidence budget from its user/provider-declared total context window. Arbitrary model IDs remain supported; Echo-8 does not maintain a brittle model-name limit table. Missing metadata keeps the established 6,000-token fallback, while review details disclose the effective evidence budget. See ADR-0043.

Fresh empty canvases receive two history-free onboarding text nodes through the normal `node.seed` command path. They remain ordinary user-editable content, but advertise `automaticRetrieval: false` through the generic context catalog: local and remote automatic indexes omit them while explicit `@` references and user-initiated canvas search remain available. Existing files without that optional flag retain normal retrieval behavior.

The AI assistant can own several open windows. Each workspace-only window record has its own assistant ID, durable conversation session, rectangle, composer height and current view. `Esc` or the panel close button only marks that instance minimized; it remains counted and recoverable from the toolbar, while the toolbar's explicit delete command is the sole destructive window/session operation. New sessions commit through `ai.assistant.openNew`, then a committed event attaches the window through a separate workspace command so document and personal-layout patches never mix. Preparation, generation, memory-save and autosave handles are session-scoped, as are status and stream-delta signals. Preparation includes the assistant identity and resolves that window's committed memory allow-list immediately before retrieval, preventing another assistant or stale UI render from changing its scope. The core task scheduler—not the model—arbitrates concurrent and queued work; its four lanes and cost budget allow two remote generations to coexist with one checkpoint, and a persistence checkpoint never cancels an in-flight generation. Reopening the primary assistant restores its last conversation, draft and layout instead of silently creating another session. The composer is the sole task/reference entry point. One declarative, domain-neutral operation catalog drives parsing, labels, suggestions and model instructions for general work, content transformation, information processing, analysis/planning and creative generation; memory directives remain a separate protocol. Compact visible `@[title]` tokens replace a node dropdown. The preparation envelope carries the corresponding stable source ID separately, so long internal IDs are not exposed in the prompt and provenance does not depend on a mutable title. Canvas-to-assistant dragging crosses plugin boundaries only through the governed `content.reference.drop-zone`, `content.reference.drag.preview` and `content.reference.drop` signals; each window has a distinct drop owner and no plugin inspects another plugin's DOM. Explicit references take priority over current-conversation context, saved-conversation index matches and general keyword matches. An explicit memory selection is a strict allow-list: search hits for an unchecked memory's original, readable index or legacy relation artifact are removed before evidence assembly. It is also an affirmative bounded evidence scope: a newly opened assistant reads the latest complete exchange from every selected memory even when the follow-up shares no lexical token, then uses lexical/semantic ranking to add more precise complete blocks. A stale selected index may trigger rebuild diagnostics but cannot suppress reading the current original. If an assistant window/session was explicitly deleted, its saved memory card can reconstruct the same stable session from `transcriptSourceId` and attach a new window through a committed event; no memory text is duplicated. With no local evidence, the assistant still answers from the model's general knowledge; it only refuses to claim real-time verification when the configured connection has no actual web grounding. Saving runs a cancellable range-read task and one transaction assembled from public mutation plans: it creates or updates one exact original-memory source, one separate readable index source and one bounded `aiMemoryIndex` record for the same session. Original memory is evidence; indexes and summaries are directories only. Compound questions scan indexes in batches of ten until query branches are covered; exhaustive requests may inspect up to fifty candidates. The weighted evidence allocator prioritizes formal authority, uncovered query branches and relevance, uses time as a tie-breaker, and admits complete user-question-plus-assistant-answer exchanges, single conversation turns, fenced-code, Markdown-table, Markdown-list, paragraph or sentence blocks under shared character and conservative estimated-token budgets instead of equal hard slices. The boundary detection and conservative token-fitting algorithms live in the internal `evidence-boundaries.ts` module, separate from session lifecycle and transaction orchestration. The visible retrieval report stays user-oriented while detailed coverage remains in the prepared-context diagnostics. The assistant panel owns workspace-only chat, memory-center, prompt-template and provider views. Its current memory appears in the shared panel title; Prompt templates use their own template icon instead of the global-settings glyph. Its derived memory catalog reports readiness and conflicts; durable broadcasts rename and pause memories, assign applicability scopes, continue the original session (or reconstruct a deleted one from the exact original) and rebuild stale or missing indexes through cancellable range scans and one transaction. Memory rename composes text-owned rename plans with the AI record/session update, then rewrites the local double-TXT pair under the new readable prefix before removing the old pair. Source edits schedule debounced rebuilds through the core task scheduler. While rebuilding, a stale anchor can only admit a range after verification against the current original; stale formal claims stay inactive. Conservative phrase detection may propose a memory directive, but only the user's confirmation inserts it. Explicit scope-aware `@确认`, `@修改`, `@废弃` and `@分支` records provide deterministic version and conflict semantics. Every provider request receives the same versioned product-side memory execution protocol, independently of the chosen endpoint. Workspace prompt templates and optional `ai.promptPolicy@1` contributors can append bounded task instructions but cannot replace those product rules. Ordinary questions proceed without a repetitive confirmation step; the header tooltip reports how many memory originals the previous answer used. Only unresolved conflicts, explicit memory-state changes or another required user decision open the nonblocking context review with sources, issues and effective budget. Generation prefers `ai.generate.stream@1`: answer and reasoning deltas are ephemeral session-tagged UI signals, cancellation discards only that session's incomplete output, and completion stores final answer in the transcript while optional provider reasoning enters a separate 800-character `aiResponseDetails` record. Reasoning is collapsible UI metadata and never becomes memory evidence; reasoning-only output is rejected instead of being presented as an answer. Provider finish reasons are normalized across OpenAI-compatible and Gemini adapters. Length-limited answers automatically make one bounded continuation request, merge without repeating the overlap, and disclose a second truncation rather than pretending to be complete. Ordinary answers do not create a write-back proposal; an explicit content-edit operation may create a source-revisioned proposal. Accepting it revalidates every source and obtains a content-owned delta plan for creating a node, appending to a node or replacing a revision-checked range, then commits the content change and accepted status in one globally undoable transaction. Provider stop aborts active requests and erases every profile key while conversation, memory and proposal document records remain restartable. See ADR-0050.

Inside the AI plugin, `memory-terms.ts` owns bounded multilingual term extraction, while `memory-retrieval.ts` owns batched recall, branch coverage, reciprocal-rank fusion, authority ordering, applicability-scope conflict detection and the derived memory catalog. These remain private feature modules: they do not gain store permissions or bypass the assistant's public capability and transaction boundaries.

Local AI-memory TXT is a personal file-system side channel, not a second document store. Each memory owns a basename with a readable title prefix and stable identity suffix; after an explicit directory grant, save/autosave schedules range-based overwrite of one original TXT and one readable-index TXT. The initial memory-directory picker is mediated by the file plugin's `file.chooseDirectoryNearProject@1` capability: it uses the current book file handle only as `showDirectoryPicker.startIn`, so the AI plugin receives the user-approved directory but never the book handle. Browsers still require that first directory confirmation. Rename writes the new pair successfully before removing the previous pair. The directory handle is stored only in personal preferences and is excluded from document snapshots, history, recovery and portable files. Paired TXT import is also a scheduler-owned two-phase operation: background file reading and public content-plan preparation precede one short standard transaction that recreates the session chunks, original source, index source and machine index. See ADR-0036.

There are currently no remaining business-feature shell plugins. New areas must enter through a protocol and an independently stoppable vertical slice rather than by extending the shell or another feature implementation.

## Delivery boundary

Development source stays modular. `portable.html` and `src/portable-entry.tsx` are a second entry point into the same feature composition, not a second implementation; persistence launch policy remains composition-specific. `npm run build:portable` builds that entry, inlines its emitted CSS and JavaScript, rejects leftover build-asset references and writes `artifacts/Echo-8.html`. Large correction-language data remains in the separately emitted `artifacts/Echo-8-text-assist-rules.txt`; it is not embedded in code or HTML. HTTP builds may read the public asset automatically. A `file://` build refuses sibling-file fetch before network access, leaves the cloud control plane disabled without a request, and lets the text-assist plugin request explicit association through its governed canvas status view. Feature code must never be copied into the build script or edited directly in the generated artifact.

Release verification has four layers. Headless TypeScript contracts cover architecture, transactions, hot-stop, migrations, bounded hostile input, large content and performance budgets. Playwright tests exercise the hosted rendered application, including plugin-view admission, toolbar undo/redo, editor and floating-panel coexistence, command-panel grouping, Esc arbitration and every governed management panel. A dedicated, separately configured Chromium performance gate imports 2,000 nodes plus one 20,000,000-character正文 and measures real DOM culling, full selection, windowed-editor opening and input latency; it is kept out of the ordinary interaction suite so failures remain attributable. After the portable build, another browser gate opens the generated artifact through its real `file://` URL, verifies the library and local cloud-boundary notice, rejects page/console/request failures and external asset loads while allowing only browser-internal `data:` and `blob:` resources, then proves that a node can be created and edited without a server. The fast local gate uses Chromium; the release workflow repeats both hosted and portable compatibility gates in Firefox and WebKit so engine-specific editing and origin behavior cannot ship unnoticed. Production dependency audit and the production build are mandatory release jobs rather than advisory local checks.
