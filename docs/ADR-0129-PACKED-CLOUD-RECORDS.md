# ADR-0129：稳定分组内共享小块

2026-11-05，有效；补充 ADR-0124、0127，不改变 .echo8 文件格式。

## 问题和归属

现场只读审计发现两本书 830 个有效块中有 750 个小于 512 字节，旧日志和无引用块已经清零。逐记录存块，加上大量小目录页，使编号、引用和索引占用超过实际值数据。云编解码和数据 Worker 拥有该组织方式；内核、插件文档模型和用户撤销协议不变。

## 版本 3

数据 Worker release 7 支持云端 book formatVersion 2/3，默认写 3。小于等于 1024 字节的序列化记录按稳定 FNV 分为 32 组，在组内按明确的字符串顺序排序，拼入目标 16 KiB 的 UTF-8 共享块；目录记录保存单块哈希、字节 offset 和原始 bytes。每组最多合并 256 KiB，其余记录继续独立分块，防止碰撞导致无界读取。较大正文继续采用既有独立 64 KiB 分块，不因为移动节点而读取或重编码。

目录同样按 32 组生成和复用，携带对应 pageBuckets/pageSizes；目录原始总量仍不超过 8 MiB，共享小值总量不超过 8 MiB。目录、块哈希、UTF-8、JSON、字节范围、记录数量、总长度、引用可达性均在提交前检查。缓存的书籍计划只保存哈希、范围与目录元数据，不保留第二份正文。

只重建补丁涉及的组。`baseline-blocks` 是 /v2 的兼容扩展，只读返回当前头引用的指定块，要求匹配编辑租约和 rootHash。基线变化则拒绝；不为每次保存复制整本书的 reader 引用。新旧格式都能读取；连接尚未升级的数据 Worker 时继续写 2。新格式的书籍拒绝被旧格式覆盖，返回 426 并保留本机修改。

读取头时通过 `format=3` 声明可读版本；旧客户端遇到新格式先收到要求刷新应用的 426，不会继续下载后再报晦涩的清单错误。

## 原地迁移

维护轮次最多合并一本空闲的格式 2 书籍，先确认旧头并取得到期维护租约。只批量读取符合条件的小记录，较大记录沿用原哈希。逐条核对小记录原始字节哈希，大记录核对引用序列，文档修订、插件目录和记录集合保持一致；随后走正式上传清单、哈希验证和 CAS 原子提交。失败保留旧头及当前引用，清理本轮临时会话并释放自己的租约。超过 256 个新块的后台迁移留给客户端的分批保存路径。

旧块继续遵守有效 reader/上传保护和 60 秒宽限，按每轮 200 条回收。读写按 75 个哈希批量查询；维护复用验证路径，一次批量存储最多 256 个已规划的新块，公共上传入口仍限制 16。D1 batch 合并请求以遵守免费实例每次调用的读请求预算。数据 Worker 升级前记录 Time Travel 书签；不重建数据库或导出用户正文。无需新增 D1 表结构，现有 schema migration 4 保持有效。

## 验证

覆盖格式 2/3 完整往返、Unicode 与未知插件、范围损坏、密集碰撞时回退、增量结果与全量编码一致、无大正文读取、编辑租约保护、reader 保护、迁移回退重试、禁止降级、基线租约/根校验及免费请求预算。代表性样本从 1451 块/1171456 字节降至 72 块/286720 字节；单节点修改读取 1 个旧块、产生 3 个新块、上传 3316 字节。这是测试样本，线上结果另行记录。

发布检查：类型和 lint 通过，543 项单元测试、191 项 Chromium 托管回归、大画布压力测试通过；最终重连条件回归 2 项通过。已重新生成单 HTML 与校验和，Chromium/WebKit 的真实 file:// 启动与编辑各 2 项通过。WebKit 定向托管首轮 4/5 通过，保存重开用例遇到一次开发资源访问错误，保持断言单独复测通过。Windows Firefox 在创建页面前发生 `_page` 运行时错误，尚未验证产品行为。
