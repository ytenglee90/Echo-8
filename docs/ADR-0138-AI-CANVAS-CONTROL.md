# ADR-0138 · AI 画布控制插件

AI 助手新增显式 `@画布操作` 任务，交给可独立停用的 `canvas-control` 插件规划当前画布对象。该路径复用现有模型连接，使用有版本的 JSON 数据计划，适用于已有 OpenAI 兼容与 Gemini 原生连接。

## 所有权与入口

AI 助手通过 `canvasControl.context@1` 获取本轮控制目录，使用 `canvasControl.offer@1` 提交模型返回的数据。生成期间隐藏结构化计划，聊天只记录人类可读的结果提示。普通聊天及原有正文写回路径保持原有行为。

控制插件只持有临时范围快照和待审查计划。用户在“画布控制”面板检查每项操作及新正文，再通过 `canvasControl.apply@1` 接受。它以带一次性令牌的内联 `canvasControl.commit@1` 执行唯一的文档事务。应用成功后才更新临时状态，提交失败保持可重试；重复点击不能重复创建对象。全局撤销一次恢复整批对象，插件停用后也使用标准逆补丁恢复。

文字、群组、连线的 owning plugin 分别提供 `canvasControl.nodesPlan@1`、`canvasControl.groupsPlan@1` 和 `canvasControl.connectionsPlan@1`。它们生成自有标准补丁，控制插件保持补丁对象及其内核授予的来源证明。删除复用 `entity.deletePlan@1`，正文变更复用分块、格式锚点和批注变换，移动复用附件计划。控制插件不读取或修改其他插件的私有命名空间。

## 范围与版本

默认只允许修改当前选中及明确 @ 引用的文字对象，选中群组包含其成员。可以在面板为下一次请求选择整个画布。每次请求最多包含 80 个对象目录，不将未选中对象的标题或正文作为控制目录发送。画布操作强制使用明确来源模式，原文仍通过现有 AI 上下文读取路径提供。已有目录和原文都是非指令性数据。

计划 v1 支持文字节点及文本框的创建、标题、全文替换或追加、位置、尺寸、标题栏/文本框颜色、显示方式；支持群组创建、标题、成员和颜色；支持普通节点及群组之间的实虚线、端点、标签和颜色，以及删除。群组至少两个文字对象，节点只能在一个群组。暂不规划中转点或批注修改。新对象以本批次代号互相引用，实际 ID 由所有者生成。

每批最多 100 项操作，正文合计十万 UTF-16 单元，结构化响应最多十三万单元。每个对象只允许一次合并更新，未知字段、非法引用、重复代号、自连、重复关系、超限和截断计划被拒绝。计划十分钟有效，每次应用重新核对本轮目录的内容和对象修订。交叉操作如果会覆盖同一存储记录，整批拒绝并要求拆分。

`canvasControlUI` 是仅本次页面的工作区命名空间，计划与模型原始操作数据不进入书籍。文件协议、原生 Gzip/CRC32 容器与已有插件数据版本无需迁移。导出仍为 `.e8`。

## 验证

合同测试覆盖混合创建、一次撤销/重做、停用后撤销、保存往返、节点组合更新、删除关联清理、范围外计划、过期修订、畸形响应、所有者规划失败和持久化准入失败。并发接受同一计划只允许一次成功。浏览器测试使用模拟模型响应，经过真实模型配置、AI 输入框、计划预览、接受、编辑冲突、撤销和文件另存重开入口。

2026-11-13 发布检查：类型检查、ESLint、578 项单元测试、Chromium 托管版 212 项回归、离线版三浏览器 21 项回归、2000 节点/两千万字符压力检查通过。最终构建再次通过三浏览器共六项控制流程检查。模型请求使用模拟接口，不消耗真实 API 额度；未验证各平台模型生成计划的成功率。离线 Firefox 的不透明来源 URL 在连接保存和请求构造两处均已修复并覆盖测试。

完整 Firefox/WebKit 托管回归首轮为 412/424，通过隔离的上一版 `c4a1fa0` 对照，十项失败也可在上一版复现：Firefox 连到中转点、40% 群组端口浮点断言、拖出视口及三档中转点间距；WebKit 实时保存时的 Blob 访问报错、扇出曲线、拖动预览一致性及 601 重叠曲线点击。另两项首轮失败（Firefox 批注剪切粘贴、WebKit 拖出视口）独立复测通过。现有跨浏览器问题未纳入本次控制插件修改，不将该全量检查标为全通过。诊断、上版对照结果及数据库备份仅保存在忽略的 `local-data/` 中，临时工作树和本次测试服务器已清理。
