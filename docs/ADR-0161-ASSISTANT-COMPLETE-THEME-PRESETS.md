# ADR 0161 · 自然语言切换完整主题

有效。补充 ADR 0079、0157、0160。

## 问题

界面的三个配套主题叫“明调、暗调、护眼”，本地识别却使用“明亮、深色”等旧词，并把主题、模式和配色分成不同语法。助手还只执行旧的文档配色命令，遗漏界面偏好。旧按钮通过两个界面命令补齐了这一步，助手和按钮因此行为不一致。

## 统一路径

公开外观协议声明三项主题名称，按钮数据、指令目录、选择列表和助手回执共用这组名称。本地纯函数 `palettePresetIntent` 匹配完整的切换请求，支持实际名称、已有浅深色别称、主题/模式/配色后缀、礼貌前缀和明确的愿望表达。否定、条件、讨论、对象名称和未完整解析的组合不能被局部匹配为主题切换。没有指定名称的“切换主题”列出全部三项。

新增外观所有者命令 `palette.applyPreset@1`，输入 `{id: bright | dark | eye-care}`，返回已应用的 `PalettePreferences`。它通过正式内联子命令依次执行既有文档配色和个人界面偏好，不使用普通嵌套排队 dispatch。文档配色仍通过各所有者的 revision-bound 外观计划，合为一次全局撤销；个人界面颜色沿用独立的 `history: false` 事务。任一子步骤失败时不回复完整切换成功。

界面按钮、原生助手路径和主题选择续接均调用这个命令。工作区新增 `appearance.preset.apply` 动作，真实声明 document 效果；自然语言目录将匹配的主题请求投影到该动作。未接入文档效果的工作区组合继续在执行前拒绝。全部指令提供三个实际主题的示例和个人用语入口。

## 兼容性

`palette.applyPresetColors@1` 继续只更新文档颜色并返回建议界面偏好，`palette.setPreferences`、旧 `appearance.theme`、`appearance.preset` 动作及既有代理提交的 `setting.kind=theme` 维持原含义。自然语言通过内部 preset 类型走新路径。已有固定计划、存储记录、书籍格式和数据库均无需迁移。新增命令及消费权限由外观和画布控制所有者声明，不跨插件导入实现。

## 验证

单元验证三组真实说法、三个完整偏好、连线和中转点颜色、一次文档撤销/重做、个人偏好不进入文档撤销、旧命令兼容、参数拒绝、插件停用和三选一续接。

托管与单 HTML 浏览器用例配置一个会拒绝模型调用的连接，实际发送三种主题名称和旧说法，核对画布颜色、工具栏 token、外观面板完整匹配状态、三项候选、实际零模型调用及零 Token。完整结果以本轮交付记录为准。
