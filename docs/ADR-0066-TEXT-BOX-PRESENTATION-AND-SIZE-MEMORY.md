# ADR-0066：文本框形态与双尺寸记忆

## 状态

已采纳；补充 ADR-0021 的画布节点远景显示规则和 ADR-0060 的插件数据迁移约束。

## 问题

文字节点原先只有标题栏加正文预览的卡片形态。简图、流程图和概念图还需要一种不承载正文预览的边框文本框，同时不能把已有正文、尺寸、连线、历史或文件兼容性变成视图层的私有状态。若转换只覆盖当前宽高，用户在两种形态之间往返时还会丢失各自调整过的尺寸。

## 决定

1. `text-node` 继续拥有同一个文本实体，并把 `presentation: card | text-box`、`cardSize` 和 `textBoxSize` 存在 `textNode` 文档记录中。转换不创建第二个实体，也不移动正文。
2. `node.presentation.set` 是有类型、版本校验且可全局撤销的正式命令。一次事务先记住离开形态的当前尺寸，再恢复进入形态上次使用的尺寸；首次进入文本框使用 240×64，首次恢复卡片使用 280×158。
3. 文本框仅在画布上显示标题。原正文和格式仍由原内容记录保留，转换回卡片后再次显示；搜索、导出和 AI 内容读取不把视觉转换误解为删除正文。
4. 文本框底色始终使用当前画布背景色，标题栏颜色作为边框和标题颜色，只保留左右连接端点。画布背景的预览、提交、撤销、重做和主题恢复都会同步反映到文本框，不新增独立文本框底色状态。标题使用 18px 字号，文本框与文字节点共用 16px 外框圆角；文本框普通外框使用 2px 描边，两种形态选中时都在同一外框边界切换为 4px 选择描边。明调及其他满足对比度门槛的浅色画布使用中灰色选择描边，暗色或中间色画布继续回退到高对比黑白极值。选中描边直接包裹节点，不增加外置轮廓或光晕；卡片标题栏的内圆角始终由外框圆角减去当前描边宽度得到，因而普通卡片为 15px、选中卡片为 12px，始终与 16px 外框严格同心。标题按文本框当前宽高自动换行并裁剪溢出；双击进入画布内标题输入，输入控件自身保持透明、无边框、无轮廓和无阴影，只由文本框外框表达选中状态；输入失焦（包括点击画布空白）即提交，卡片双击仍打开完整正文编辑器。
5. 文本框不参加 ADR-0021 的远景卡片降级。画布缩放只作用于世界变换，不把文本框替换成填色标题块，也不移除其转换和缩放控件。空间裁剪、连接几何和选择协议仍使用当前活动尺寸。
6. 文本框与卡片共用右下角缩放交互，但使用各自的最小尺寸；缩放、恢复初始大小和自动排列都更新当前形态对应的尺寸记忆。
7. `text-node` 数据版本升为 2。`1 -> 2` 迁移把旧记录明确标为卡片，并用旧的活动宽高初始化 `cardSize`；迁移不改正文、颜色、位置、标识或时间字段。
8. 卡片和文本框都不渲染节点本地转换按钮。顶部“选中项工具”组在自动排列与调色盘之间提供统一的高对比度主按钮；`node.toggleSelectedPresentation` 为选中的文字节点逐个切换形态，并以一个事务提交。“文本框与文字节点相互转换”同时注册为公开操作和无默认按键的 `text-node.toggle-selected-presentation-shortcut`，快捷键中心把操作与绑定显示在同一行并允许用户自行设置，组件不监听全局键盘。

## 结果

- 卡片与文本框保持同一个稳定节点 ID，因此既有选择、连线、分组、剪贴板和持久化协议继续工作。
- 转换本身以及转换后的尺寸修改都进入全局历史，撤销和重做可恢复完整形态与几何。
- `ContentSummary` 公开当前形态和活动形态的缩放限制，画布无需导入文字节点实现。
- 公共指令注册表新增 `node.toggleSelectedPresentation`；这是加法兼容修改，不改变既有 `node.presentation.set` 或文件格式。
- 文本框隐藏正文但不丢弃正文；这是可逆的展示选择，不是内容裁剪。

## 验证

- 合同测试覆盖旧记录迁移、正文保留、两套尺寸往返恢复以及转换的撤销/重做。
- 浏览器测试覆盖文本框底色实时跟随画布背景预览与提交、标题色描边、左右端点、远景样式稳定、自动换行、无内框的双击标题编辑、空白失焦提交、拖拽缩放、两种节点形态均无本地转换按钮，以及工具栏按钮完成双向转换。
- 合同测试覆盖快捷键贡献存在、无默认冲突、选中节点批量切换以及单事务历史。
- 浏览器测试从快捷键中心搜索该操作、自定义组合键，并用新按键转换选中的文字节点。
- 类型检查、Lint、完整合同测试、浏览器测试、便携构建与便携浏览器测试继续作为发布门禁。
