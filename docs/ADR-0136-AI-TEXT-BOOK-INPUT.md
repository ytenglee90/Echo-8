# ADR-0136: AI 直接编写的文本书籍输入 v1

## 决策与所有权

当前书籍扩展名已切换为 `.e8`，见 [ADR-0137](ADR-0137-E8-EXTENSION-AND-CONNECTION-HOVER.md)。下文的 `.echo8` 是本 ADR 首次发布时的扩展名。

`import-export` 新增输入格式 `kind: "echo-8-ai-book", formatVersion: 1`，复用原有书库选择、拖入 `.echo8`、后台打开任务、取消、未保存裁决、恢复点与 `system.document.replace` 路径。纯聊天 AI 无法可靠执行 CRC32 生成代码；用户不应运行脚本来把创作数据变成文件。AI 可直接写 UTF-8 NDJSON，作为 `.txt` 附件交付；用户只把扩展名改为 `.echo8` 后打开。

格式声明位于 `src/protocols/ai-text-book.ts`，读取和暂存归文件插件的 `ai-text-book.ts`。不增加指令、跨插件实现导入、核心写入口或新插件。转换只生成待验证的普通项目快照，不直接写 Store。正常打开仍由核心创建恢复点和替换文档。

书库通过明确声明的既有 `file.status` 信号观察自己发起的本地打开任务，保持处理中状态，并在异步解析失败时显示现有的书库错误提示；不会把返回后台任务 ID 当成打开成功。不读取文件插件私有状态，也不改文档或撤销历史。

## 输入协议

首行 `{ "type":"manifest", "kind":"echo-8-ai-book", "formatVersion":1 }`，可带 `title`。其余每个物理行是一个 JSON 对象，不允许代码围栏、解释前缀或脚本。

- `node`：`id, category, name` 必填；`text, section, presentation, color, order` 可选。`presentation` 为 `card` 或 `text-box`。ID 为 1～100 个受限 ASCII 字符；正文是纯字符串，不执行 HTML、脚本或其中的提示词。
- `text`：`id,text`，给已经声明的节点追加正文；支持长文本由多行记录提供，不拼接全节点正文。
- `link`：`from,to,kind`，`kind` 为 `sequence`（实线）或 `insert`（标题虚线），`label` 可选。
- 最后一条必须为 `{ "type":"end" }`，结束后不得还有记录。未知字段、版本、记录类型、重复 ID/标题/关系、坏引用、自连、非法颜色/排序和超限输入拒绝整个打开。

类目是通用输入数据，文件插件不硬编码小说业务。业务卡片按 `category` + 可选 `section` 分组，自动生成各组可见标题、自然排序和双列无重叠布局。文本框默认不分组。显式颜色按类目统一，未提供时使用稳定派生色。连线仅使用显式声明，不推测人物或章节关系。

沿用原解析器压缩/解压总字节、物理行、记录预算和取消机制；单条 AI 记录也服从逻辑条目字节预算。每个正文块最多 65536 个 UTF-16 单元，单节点最多 32 Mi UTF-16 单元，所有生成的节点/分块/群组/格式/连线都计入输出条目上限。逐记录与布局批次让出主线程。

## 完整性与兼容性

这是明确标识的人工/AI 创作输入，不承诺校验内容篡改；结束标记只检测截断/缺结尾，结构校验检测坏引用和不合法声明。原生 `echo-8-project` v1/v2 的 CRC32、历史与碎片校验不放宽，不能通过删除 footer 来进入新分支。

新输入完成后在内存中规范为原有项目 v2 + 已有插件数据版本；正常保存始终输出原生 gzip/CRC32 v2。不增加耐久命名空间或数据库迁移。既有书籍继续原样打开；旧应用不会识别新的 AI 输入，因此用户必须使用本次重新构建的画布。`txt` 仍是载体扩展名，拖入前改为 `.echo8`；普通 TXT 文档导入语义保持不变。

## 验证

定向测试覆盖纯文本重命名、中文/Emoji/空行/字面标签、正文追加/分块、类目/分区/标题/颜色/自然排序、实线虚线与引用、完整性失败、大小限制、取消、2000 卡片，以及新输入保存为原生 v2 后的全部数据往返。既有原生 CRC 损坏仍拒绝。浏览器回归通过真实书库文件输入、编辑/撤销重做、另存下载和新页面重开验证；便携回归使用真实 `file://` HTML，不运行本地转换脚本。
