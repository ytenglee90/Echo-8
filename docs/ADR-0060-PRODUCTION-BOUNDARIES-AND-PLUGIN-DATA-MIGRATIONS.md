# ADR-0060：生产输入边界、插件数据迁移与热停机

## 状态

已采纳。

## 问题

日常生产使用不仅要求正常路径可用，还必须明确处理不可信书籍输入、插件升级和运行中停用。此前 `.echo8` 解析器会验证格式与 CRC，但没有同时限制压缩体积、解压后体积、逻辑记录大小、分片数和记录数；插件描述只有实现版本，无法区分实现升级与持久数据结构升级；能力注册表在插件停用时移除提供者，但停用边界前已经进入的异步调用可能继续访问正在拆除的资源。旧版正文编辑器还可能在撤销/重做后，把浏览器稍晚送达的 `input` 事件按旧正文直接提交。

## 决定

1. `.echo8` 解析采用分层硬限制：压缩输入与解压输出分别不超过 256 MiB，单个逻辑记录不超过 64 MiB，每条记录最多 1024 个分片，全书最多 250,000 条记录。读取流一旦超限或取消立即终止；CRC、记录顺序、重复键与格式验证仍然全部执行。
2. 每个插件 manifest 必须声明整数 `dataVersion >= 1`。书籍中的插件描述保存该版本；旧书缺失时按 1 解释。实现 `version` 用于代码/能力兼容，`dataVersion` 专门描述插件拥有的文档命名空间结构，两者不能互相替代。
3. 数据升级只能声明连续的 `n -> n + 1` 迁移链。迁移在替换当前文档之前，对相关插件命名空间的结构化克隆执行；结果只能包含该插件原有或当前声明的文档命名空间。任一步失败、越权写入、链不连续或书籍版本高于运行时支持版本时，整个打开操作失败，当前文档和传入载荷均保持不变。
4. 成功迁移后更新插件描述和文档 revision。旧格式 v1 书籍携带的撤销/重做补丁针对迁移前结构，因此发生任何数据迁移时清空导入历史，避免撤销把旧 schema 重新写回。未知插件的数据与描述继续原样保留。
5. 插件停止、暂停或卸载先在能力注册表关闭该 owner 的新请求入口，再中止支持 `AbortSignal` 的在途调用，并等待所有已经进入的调用 settled，之后才释放任务、worker 和其他资源。重新启动时显式恢复入口。
6. 编辑器在撤销、重做或文档替换后把已打开正文标记为 authority stale；下一次浏览器输入先读取权威正文，并将浏览器给出的旧快照 delta 重基到当前正文后再提交。连续输入仍按同一权威 epoch 递进。
7. AI 记忆保存允许不同会话并发生成回答，但“内容节点规划—记忆事务提交”使用插件内串行临界区，避免两个保存任务基于同一标题目录快照进行冲突提交。

## 兼容性

文件容器格式仍为 version 2；新增的 `dataVersion` 是插件描述中的向后兼容字段。旧书按数据版本 1 打开。未知插件保持不透明。超出安全预算的文件现在会被明确拒绝，而不是继续消耗无界内存。内置插件当前数据版本均为 1，不需要即时迁移。

## 验证

- 合同测试覆盖压缩膨胀、超大逻辑分片、迁移顺序、迁移失败原子性、未知数据保留和高版本拒绝。
- 生命周期测试覆盖热停机关闭新能力请求、协作取消并等待在途 Promise。
- 编辑器纯函数与浏览器测试覆盖撤销/重做后的即时输入重基。
- AI 合同测试覆盖两个会话同时生成并分别保存记忆。
- 发布门禁执行生产依赖审计、类型检查、静态检查、全部合同测试、真实浏览器极限性能测试和生产构建。
