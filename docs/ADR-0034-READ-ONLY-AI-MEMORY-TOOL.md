# ADR-0034：只读本地记忆工具

## 状态

已采纳。该编号为原始唯一决策编号；原重复编号的文本辅助决策已整理为 ADR-0061。

## 背景

自动混合检索适合大多数“回忆/核对/分析”请求，但模型有时会在已经准备好的来源之外，需要更精确地确认一个历史决定、约束、术语或版本。把所有历史原文提前塞入提示词既慢又会降低相关性；让模型拥有画布写权限则会破坏用户确认和事务边界。

## 决定

Echo-8 为支持 OpenAI 兼容 Function Calling 的模型连接提供一个受限工具：`search_memory`。

- 工具只在自动检索模式、非普通对话意图，且用户在该 OpenAI 兼容连接的“高级连接设置”中明确开启时暴露。Gemini 原生连接及未开启的连接维持现有混合检索，不会因工具缺失失败。
- 参数只有 `query` 和可选的 `max_results`（1–4）；不接受来源 ID、画布节点、文件路径、命令或任何写入参数。
- 每次回答最多执行一次；模型请求未知工具、重复调用或非法 JSON 时只收到受限错误结果，不能改变应用状态。
- 工具仅查询已保存、已启用、与原文修订匹配的对话记忆。它使用现有索引定位，再读取最多四个完整、范围受限的原文证据块。索引过期、来源不可读或结构不完整的片段不会发送给模型。
- 工具输出始终包在 `untrusted-memory-content` 边界中；模型必须把它视作参考资料而不是指令，并在实质依赖时标记对应记忆标题。
- 调用、工具输出、API KEY、向量和搜索缓存都不写入画布文档、历史或 `.echo8` 文件。唯一的用户可见记录是本轮完成状态“已按需查询本地记忆”。

## 架构与兼容性

这是 `ai.generate@1` 的可选 `tools` 字段和流式 `tool-call` 事件扩展。生成请求、网络访问和调用循环仍由 AI 提供者与 AI 助手插件各自拥有；工具执行在 AI 助手插件内通过 `context.read@1` 的现有受限读取能力完成。没有新增持久化命名空间、文件格式或文档迁移。

## 被拒绝的方案

- 将全部记忆正文附在每一轮提示词：上下文膨胀、延迟和误召回都会增加。
- 让模型直接读取或修改画布：会绕过来源范围、隐私、事务、撤销和用户确认。
- 在普通闲聊中静默调用工具：违背普通对话不自动检索历史记忆的现有承诺。

## 验证

- 流式工具调用分片可被完整组装，且不会被当作最终回答显示。
- 工具参数、显式来源模式、版本匹配和不可信证据边界均有单元测试。
- OpenAI 兼容提供者的请求正文与 SSE 工具分片有内核契约测试。
