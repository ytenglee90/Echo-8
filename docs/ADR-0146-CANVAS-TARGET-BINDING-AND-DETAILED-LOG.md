# ADR 0146 画布正文目标绑定与详细操作日志

状态为有效，补充 0138、0143、0144、0145。

## 真实请求中的故障

用户发送“填入角色卡”“在角色卡节点里，设计人物”时，旧路由进入普通问答。“垂直排列所有节点”“宫格排列所有节点”没有本地排列规则，模型请求沿用选区范围，导致目录为空。对话原文中的旧能力否定被后续请求再次读取。旧日志只有阶段、状态和时长，无法说明对象命中、计划内容和待确认原因。

## 对象与执行路径

常见前置排列说法直接编译为原有排列操作。“所有节点”沿用本地筛选取得实际节点 ID。省略范围的排列先使用本轮对象或选区，均为空时读取当前画布的可自动检索文字对象。模型计划也按明确的全画布措辞捕获范围，保留原有 80 对象上限和修订校验。

正文写入使用 content 意图，canvas-control 提供只读 canvasControl.bindContent@1，复用原有名称、检索权限与候选解析取得真实目标。AI 上下文只读取绑定正文的有界片段，模型生成 update-node 计划。目标模糊时先显示候选，点选后 canvas-control.resume@1 通知原会话，ai-assistant 核对来源及原请求后，通过已有 prepare 指令继续。已更换的请求不能被旧候选恢复。新建节点的身份单独保存在会话临时状态中，支持“刚新建的那张角色卡”。

canvasControl.result@1 在实际应用、失败或放弃后通知原会话。助手核对当前请求后同步状态栏，手动应用成功后显示真实提交结果。

当前协议与目录持续作为能力依据。构造画布请求时省略含旧画布能力否定的助手角色消息，保存的原始对话保留。已有明确正文目标时，空更新计划进入一次有界修正，修正后仍无更新则报错。

## 日志协议 v2

新增 system.operationLog@2 查询与 system.operationLog.stage@2 信号。旧查询继续返回原有字段。v2 在会话内记录受限枚举和计数，包括本地或模型路径、动作类型、作用范围、对象与候选数、操作分类计数、当前步骤、待确认原因、失败类别及 HTTP 状态码。每个阶段最多保留 24 次转换。核心验证拥有者和所有字段，任意提示词、标题、正文、错误原文及扩展字段均不会进入记录。

诊断中心展示这些信息，并可展开实际步骤。待确认时间显示为等待确认，执行提交记录为独立步骤。格式修正、过期修订、插件不可用、模型失败与提交失败使用不同原因。正文和现有对象的修改继续遵循原有审查设置与事务路径。

## 兼容与验证

节点、书籍、持久配置和数据库格式沿用现有版本。新增绑定能力与通知使用独立 v1，日志增强使用 v2。日志为内存数据，旧消费者可以继续使用 v1。

回归使用实际反馈中的原句，验证无选区全画布排列、零模型调用、真实正文目标与应用、候选后继续模型计划、旧能力否定的上下文隔离、日志步骤与计数、v1 响应兼容、快照隔离及隐私字段排除。模型请求使用模拟接口。
