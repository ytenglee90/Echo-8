# ADR-0049：统一 Unicode 可见字符统计

## 状态

已采纳；ADR-0059 恢复并统一了本决策的产品主显示口径。ADR-0062 进一步规定所有实现必须复用同一个核心 Unicode 统计模块。

## 问题

界面曾混用三种不同口径：顶部选中项统计直接累加 JavaScript 字符串长度，编辑器底栏统计全部字素，超长正文首次打开又把 UTF-16 长度当作字数。因此空格和换行会抬高编辑器数字，组合 Emoji 在顶部可能被算成多个字符，同一份正文在两个位置显示不同结果。

## 决策

- 用户可见的正文“字符数”统一定义为：Unicode 字素簇数量，但不统计空格、制表符、换行等空白字符。
- 一个汉字、标点、英文字母或数字各计一个；由多个码位组成的组合 Emoji 计一个。标题不计入正文字符数。
- UTF-16 单元数、包含空白的字素数和分词后的词数继续作为不同的协议字段保留，不能再用其中任何一个冒充界面字符数。
- 文本节点插件作为正文数据所有者提供 `content.metrics@2`。调用方只提交已知节点 ID；能力返回合计与逐节点的 UTF-16、字素和非空白字素统计。
- 编辑器曾按 ADR-0051 单独显示写作单位；ADR-0059 已将主显示重新统一为本 ADR 的非空白 Unicode 字符指标，`content.metrics@3` 的写作单位字段仅保留兼容用途。
- 统计扫描沿用正文分块读取和内容签名缓存，不拼接超长正文；任务支持取消并定期让出主线程。
- 顶部状态栏先通过选择插件展开群组，再向 `content.metrics@2` 查询实际文字节点。过期选择查询会被取消，不能以旧结果覆盖新选择。
- 编辑器打开时从同一能力取得精确总数；正常输入只按本次文本差量即时更新，提交后的失效广播再以正文所有者的精确结果校准。

## 兼容性

这是一个只读能力和显示口径升级，不修改正文、历史或 `.echo8` 文件格式。旧的 `content.metrics@1` 继续保留给确实只需要 UTF-16 长度的调用方。

## 验证

- 内核测试覆盖中文、英文、空格、换行和由零宽连接符组成的家庭 Emoji。
- 选择一个群组时，统计其内部所有文字节点且不把群组本身算作文字节点。
- 浏览器测试验证画布节点标题栏、编辑器底栏和顶部“选中节点 / 字符数”对同一正文给出相同结果，并采用相同的千位格式。
- TypeScript、Lint、内核测试、浏览器回归测试和便携单文件构建仍是发布门禁。
