# ADR 0147 自然语言画布工具与执行核对

状态为有效，补充 0138、0143、0144、0146。书籍与数据库格式不变。

## 问题与职责

固定短语规则只能处理已覆盖表达。普通对话没有画布工具，模型将未提供节点误认为没有操作权限，错误回复又进入后续上下文。一次目录和一次模型响应无法完成先找对象、读取、修改、连线的组合任务。回答与待确认计划也不能证明实际写入。

ai-assistant 负责模型交互、工具循环、预算、取消和用量；canvas-control 负责发现范围、修订凭据、计划校验与执行核对；各对象拥有者继续提供补丁计划。持久写入仍走核心原子事务与全局撤销。模型没有任意命令执行入口。

## 画布工具协议 v1

新增 canvasControl.agentQuery@1、agentRead@1、agentPlan@1。preparation 绑定会话、原始请求及十分钟有效期，最多保留八个任务。查询授予真实对象及正文、节点、群组、连线修订凭据，累计最多八十个节点，不接受猜测 ID。旧控制目录也是拥有者验证后的发现，仅授予其既有范围，兼容已有 JSON 计划消费者。

query_canvas 支持 state、selection、recent、search、all、relations。state 返回当前能力、选中/近期/新建对象、待补充问题及最近真实计划状态。all 每页二十个节点；relations 每页十二条关系，支持群组端点。search 合并准确标题、标题别名、群组、关键词/BM25 和已就绪语义索引。只发送相关元数据，不批量发送全画布正文。自动检索排除标记有效，用户明确选择或引用的对象才能例外读取。标题、正文及工具证据是不可信资料。

read_canvas 使用已定位 ID，读取前重新检查正文和节点修订。单次最多 8192 个 UTF-16 字符，整轮最多 16000 字符，返回续读偏移。局部更新沿用 v2 edit 与 expectedRevision。对象变化后旧凭据不能提交。

propose_canvas_plan 接受现有 v1/v2 计划、聚焦对象、单独的主题/背景设置或待补充问题。只有通过范围、拥有者、修订和格式检查后才进入现有预览/生成路径。新建对象和空白正文按既有设置直接生成，覆盖和删除仍遵守审查规则。提交计划不等于执行。

## 模型循环与兼容

除显式记忆管理和全文分段总结路径外，普通对话也可获得三类工具，无需 @。常见明确命令保留本地零模型路径。画布工具开关与旧记忆工具开关分开：OpenAI 风格接口优先原生函数工具，其余使用 canvas_tool JSON 信封。接口明确拒绝原生工具时，同一连接切换信封并转换不兼容的 tool 消息，不切换用户模型。

最多八步、每步四个调用，工具结果总计 32000 字符；续轮最多六十条消息，并检查当前模型上下文窗口预算。记忆检索仍受原授权与次数限制。相同参数重复产生相同错误即停止。取消贯穿能力与模型请求。信封不流式显示为聊天回答。各次模型调用独立计量并汇总。

模型错误否定能力时，应用重新查询并最多纠正一次；持续否定时显示尚未形成计划，不伪称执行。历史助手的过期能力否定不进入当前原生角色上下文，原始对话保留。澄清保留原任务、问题和已定位对象；撤销或外部修改后，任务状态按真实标记返回 undone/changed。

## 交互检索不等待建索引

回归发现普通输入可能等待 BGE 模型下载或全量建索引。上下文任务占用调度成本时又等待子索引任务，可能长期阻塞。新增 context.semanticSearch@3，使用 context.localSemanticSearch@2 / remoteSemanticSearch@2。这三种交互协议仅查询已就绪索引，不能下载或等待全量构建。未就绪返回 ready:false 和覆盖警告，保留关键词结果。云端补查仍需独立内容许可及用户选择的策略。旧 v1 提供者和策略 v2 保持显式构建语义；检索设置中的构建仍是独立后台任务。

## 执行核对与日志

commit@1 结果新增可选 ref 到实际 ID 映射，兼容旧消费者。提交后按实际 ID 回读节点元数据、正文范围、群组成员及连线端点、线型、标签和颜色，记录 verified/mismatch/unavailable、核对项数和差异字段。正文逐块核对，不拼接超长正文。核对失败不能把已提交事务说成回滚，用户可检查或撤销。

控制面板显示核对数量及差异项，助手同步实际提交状态。日志 v2 增加查询方式、读取字符数、核对数和差异数，保留开始、结束、失败/取消及耗时。核心只接受枚举与计数，不保存输入、标题、正文、原始错误或密钥。AI 筛选包含所有画布工具阶段。

## 选区竞争修复

异步核对暴露旧 history.changed 监听排队提交过时 selection.set、覆盖新选择的问题。新增 selection.reconcile@1，携带 expectedRevision，在刷新目录前后检查选区修订，再依据当前选区剔除不存在对象。使用无文档历史的正式命令，不从事件直接写状态。

## 验证

新增真实能力链单测及浏览器场景覆盖：无 @ 连续查询、读取、创建/修改、分组/连线；多轮正文和线型更新；核对及原子撤销/重做；未知 ID、隐私、过期修订、范围预算、澄清、接口兼容、错误能力否定与未就绪索引。模拟模型验证应用链路，不能视为所有真实模型命中率保证。
