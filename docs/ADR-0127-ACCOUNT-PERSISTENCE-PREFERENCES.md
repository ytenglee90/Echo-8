# ADR-0127：个人账户的自动保存与恢复保留设置

日期：2026-11-05。状态：有效；补充 ADR-0081、0124、0125。

## 归属与协议

自动保存间隔和自动保留数量属于个人设置，由 core.persistence 保存与执行，由 cloud-sync 负责账户传输；UI 继续通过 import-export 的公开指令修改。设置不进入书籍、共享文档或撤销历史，也不传输恢复副本正文、文件授权或个人密钥。

新增 `system.persistence.preferences@1` 查询和 `system.persistence.applyPreferences@1` 指令。版本 1 负载严格只含 `schemaVersion: 1`、`autosaveIntervalMs`（既有实时/定时/关闭枚举）和 `recoveryRetentionLimit`（null 或 8/20/50/100）。提交成功后广播 `system.persistence.preferences.changed`；旧的单项设置指令继续兼容并发布同一通知。账户应用先保存当前文档及撤销历史，再在一个 IndexedDB 事务中写两项设置和整理超限副本，失败不部分应用；垃圾回收失败不撤销已经成功的设置写入。

如果数量策略没有改变，仅写入实际变化的保存间隔，不重新捕获整份文档或扫描恢复目录。需要变更数量策略和整理副本时才进入上述维护事务。

数量限制仍在本机原位置明确确认，提示该政策随账户同步。另一设备恢复已确认的有限保留政策时，同样在当前文档安全检查点之后整理旧副本。null 明确保留“不限制”，0 间隔明确保留“关闭”，都不能被默认值替换。

## 账户同步与冲突

用户数据 Worker 新增 `/v2/preferences` GET/PUT，负载内部版本为 1；PUT 必须携带 expectedRevision。只接受上述两个字段及版本标记，按认证身份隔离数据，以 CAS 拒绝并发覆盖。首次连接且账户尚未配置时上传现有设备选择；新设备下载账户选择。同步基线绑定用户和安装 ID，换账户不会把旧账户设置上传到新账户。两端均变更时保留本机选择，提供“使用本机保存设置 / 使用账号保存设置”的显式决议。

同步使用声明的核心查询、子指令和后续队列，不能在正式指令内等待普通 dispatch。设置变化合并为一次短延迟同步；插件停用取消其定时资源。断网时本机设置继续持久保存，下一次连接/同步通过基线差异补传。

## 迁移与兼容

数据 Worker 发布版本升为 6，D1 schema migration 4 只新增 `account_preferences`，可重复执行，不改已有书籍或快捷键表。旧安装仍能编辑和保存书籍；升级个人数据服务后启用这两项账户同步。旧浏览器不调用新接口，旧文件和 IndexedDB v5 无结构变化，不需要重写 .echo8。

## 验证

覆盖全部保存间隔与数量枚举、关闭/不限制往返、非法字段拒绝、并发 CAS、身份隔离、旧库幂等升级；真实浏览器使用隔离设备上下文验证恢复、刷新、冲突决议以及本机恢复正文不跨设备传输。保留既有恢复管理和快捷键回归。

本次交付验证：类型检查、Lint、535 项单元测试、Chromium 全量 189 项、WebKit 账户与恢复管理 6 项均通过；两个引擎各 2 项真实 file:// 离线用例及极端画布性能检查通过。单 HTML 已重新构建并核对 SHA-256。Firefox 在 browserContext.newPage 阶段发生本机运行时错误，页面尚未创建，兼容性不能视为通过。开发服务器排除 local-data 本机资料，避免归档和诊断文件占用文件监视器。
