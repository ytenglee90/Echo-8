# ADR-0038：打开书籍裁决与大型个人文本资源

## 状态

已接受。

## 问题

原先只有在用户已经选中或拖入目标书籍后，文件插件才发现当前书籍未保存。关闭提示只会取消打开，与产品要求的“取消保存后继续打开”不一致。另一方面，便携 `file://` 页面无法静默读取同目录纠错 TXT；保留文件句柄仍可能在重启后失去权限，而普通个人偏好又有 256 KiB 上限，装不下当前规则包。

## 决策

1. 新增 `file.requestOpenProject`。按钮入口先广播请求，由文件插件根据核心文档修订判断是否可以立即打开原生选择器。
2. 未保存裁决只存在于文件插件内存，分为 `picker` 与 `file` 两种目标，以及 `needs-decision`、`ready-to-choose` 两个阶段。
3. 对按钮目标，界面先在当前用户点击中打开原生选择器；只有确实选中文件后，才广播 `file.proceedPendingOpen` 发放两分钟内有效且只能消费一次的随机授权。真正的 `file.openProject` 必须消费该授权，或重新执行脏状态检查。取消原生选择器不会提前清除提示。
4. 拖入目标已经存在，裁决后直接打开；按钮目标尚未选择。原生 Save As 完成后，由于浏览器的用户激活通常已被消耗，界面提供一次明确的“选择要打开的书籍”点击，而不伪装成可以可靠自动弹出第二个系统窗口。
5. IndexedDB 升级到版本 5，新增 `personalAssets` 表。`system.personalAssets.get/set` 只允许插件读取和写入自己的命名空间，写入需要 `personal.assets.manage` 权限。
6. 个人文本资源不进入 Store、撤销、checkpoint、恢复点或 `.echo8`。单条文本最多 16 MiB；普通偏好的 256 KiB 上限保持不变。
7. 文本辅助首次导入 TXT 后保存完整字符串；启动时优先读取该副本。存在有效副本时不检查旧文件句柄或权限。重新导入会覆盖副本，并同步当前隐藏规则资源。

## 结果

打开流程不会在用户选完目标后才突然要求保存；按钮与拖放共用一个裁决中心。大型规则不会污染书籍文件，也不会因为普通偏好大小限制而失败。浏览器清理站点数据、切换来源或不支持 IndexedDB 时仍可能丢失本机副本，因此外部 TXT 继续作为可携带来源。

## 验证

内核测试覆盖打开请求、一次性授权、拖入文件保存后打开、超过 256 KiB 的个人文本资源和书籍隔离。浏览器测试覆盖首次导入后刷新仍自动激活规则，以及原生选择器打开后提示仍保留、选中文件后才继续打开书籍。
