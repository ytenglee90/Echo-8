# ADR-0056：本地 BGE 语义检索作为受控的并列提供器

## 背景

BM25 对专有名词和精确短语很可靠，但无法稳定覆盖“服务器崩了”与“502、内存溢出”这类不同措辞。远程向量连接能解决这个问题，但必须由用户单独提供连接、KEY 和画布内容外发授权。

## 决策

增加 `local-semantic-provider`：

- 使用量化 `Xenova/bge-small-zh-v1.5` 与固定版本的 ONNX WASM 运行时，在浏览器受管 Worker 中按需加载和推理；模型会话和来源片段只保留在运行时内存。
- 以 `context.semanticSearch@1` 并列提供结果，现有检索层继续用 RRF 与 BM25、已配置的远程向量结果合并；语义结果只扩大召回，最终仍回读有版本的原文作为证据。
- 本地提供器复用公共的分块与来源采样模块，确保与远程提供器一样尊重 `automaticRetrieval`、范围读取、超长来源上限和绝对偏移。
- 新增内核 `network.ai.model` 权限和固定资产下载接口。插件不能提交 URL、请求头或画布文本；内核只允许版本固定的 BGE 模型、分词器和 ONNX WASM 运行时，并限制大小、并发、超时、重定向来源、凭据和 referrer。
- 公共模型文件允许浏览器 HTTP 缓存；缓存中不写入画布文本。关闭本地检索、清除运行时缓存或停止插件时，主动释放 Worker 模型会话和向量索引。
- 已完成的向量索引可写入内核拥有的 `personalAssets` IndexedDB 存储，作为有上限、可丢弃、可重建的设备本地派生缓存。记录只包含固定模型版本、来源 ID、来源修订、块指纹、绝对范围、覆盖方式和 Float32 向量，不保存标题、正文摘录或 Prompt；它不进入文档、历史、恢复点或 `.echo8` 文件。
- 缓存编码、解码和校验在受管 Worker 中完成。插件重启后仍重新范围读取当前原文并计算块指纹；只有指纹完全一致的块才能复用向量。版本不兼容、记录损坏、超过 15 MiB 上限或持久化不可用时直接丢弃/截断缓存并安全重建，不影响 BM25 回退。
- 模型初始下载地址保持固定；Hugging Face 模型文件可仅沿 HTTPS 默认端口跳转到 `huggingface.co` 或受限的 `.hf.co` 存储/CDN 子域。该范围用于兼容 Hugging Face 官方持续演进的区域 CDN，不能由插件传入任意 URL、请求头或正文。
- ONNX 运行时下载固定为公共入口 `ort.wasm.min.mjs` 与它唯一的固定后端 `ort-wasm-simd-threaded.mjs`。Worker 仅将入口运行时解析的这个固定后端文件名替换为已审核的 Blob 后端 URL，并将该 URL 保留到模型卸载；运行时 WASM 仍以审核后的字节传入，不允许模块自行扩展网络来源。

## 后果

- 首次有语义检索需求时需要下载约 40 MB，低性能设备的首次建索引会更慢；设置面板显示六个固定资源的当前阶段，并允许取消当前索引。取消会中止受管下载、丢弃半成品索引并立即回退 BM25。
- 不依赖对话平台、嵌入 KEY 或远程画布内容授权；Worker 或模型不可用时返回空语义贡献，BM25 仍可正常工作。
- 不引入具备 Node 后端的模型运行时；ONNX 和分词器均只在 Worker 的动态导入路径中加载，避免增加常规 AI 对话的网络与运行时开销。
- 再次打开或热重启插件时，未变化的块不需要重复生成文档向量；查询本身仍需加载模型并生成一次查询向量。持久缓存只是加速层，原文和修订号始终是检索证据的权威来源。
