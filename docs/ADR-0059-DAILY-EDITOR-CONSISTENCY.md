# ADR-0059：日常编辑一致性与会话恢复提示

## 状态

已采纳。

## 问题

编辑器内部拖拽选中文字时，旧实现只在目标位置插入文本，原选区仍然保留，表现为复制而不是移动。编辑器底栏展示 ADR-0051 的写作单位，而顶部展示非空白 Unicode 字符数，导致同一正文数字不一致且底栏不计标点。浏览器原生全屏可能先消费 Escape，只留下 `fullscreenchange`，使应用仍停留在沉浸写作。核心检查点通知还把仅限当前会话的恢复副本描述为“完整本地存档”，容易被理解为已经保存 `.echo8` 文件。

## 决定

1. 同一编辑器正文内拖拽非空选区使用公开命令 `content.moveRange`。目标偏移以移动前正文为准；落点位于原选区内时不操作。文本所有者在一个事务中移动分块正文、格式标记和 `content.anchorMovePlan@1` 提供者的锚点，进入一次全局撤销。外部文字拖入继续使用复制语义。
2. 工具栏、编辑器全文和编辑器选区统一展示非空白 Unicode 字素数。标点和组合 Emoji 计入，空格、制表符和换行不计入。`content.metrics@3` 的旧写作单位字段继续保留以兼容现有调用，但 ADR-0051 的“编辑器主显示采用独立写作单位”决定由本 ADR 取代。
3. Escape 仍按局部临时对象、受管表面、全局快捷键的顺序处理。Shell 额外监听 `fullscreenchange`；如果原生全屏从活动变为关闭而 `editor.immersive` 仍是顶层模态表面，则只分发一次 `system.ui.escape`。沉浸状态不直接从 DOM 事件写入 Store。
4. 核心 persistence 只把“会话恢复副本/检查点”作为后台容错能力。在 `fresh-session` 启动策略下明确说明它仅用于当前打开期间。例行检查点成功保持安静，不再显示全局成功卡片；只有恢复写入失败或启动时确实存在可恢复内容才进入全局提示。只有持有真实文件目标的 import/export 插件可以报告书籍文件已经保存或自动覆盖。
5. 打开或激活右侧文本编辑区只改变编辑器工作区，不隐式分发画布聚焦命令。双击画布文本节点、搜索结果或其他内容入口都保留当前相机位置；需要居中选中项时，用户继续使用独立的“聚焦选中项”操作。
6. 普通双击文字节点使用 `editor.open` 的替换模式，右侧只保留当前节点；Shift + 双击使用显式追加模式，继续遵守最多三个编辑区及第四个选择替换的规则。右侧文本编辑区和属性面板通过 ADR-0025 的统一仲裁双向替换，面板让位时关闭整组编辑区，但 Escape 和单个关闭按钮仍只关闭当前编辑区。

## 兼容性

新增一个内置命令和一个可选锚点规划能力，不修改正文、历史补丁或 `.echo8` 文件格式。旧项目无需迁移。写作单位仍在协议中保留，因此不要求数据迁移。

## 验证

- 纯函数测试覆盖选区向前、向后移动和选区内落点。
- 内核测试验证正文、格式、注释锚点和一次撤销属于同一事务。
- 浏览器测试验证真实编辑区拖拽不会复制，并可由一次撤销恢复。
- 浏览器测试验证标点、Emoji、空白和顶部/编辑器统计一致。
- 浏览器测试模拟原生全屏先退出且不产生页面 Escape，沉浸表面仍会关闭。
- 浏览器测试验证双击文本节点会打开右侧编辑区，同时画布相机变换保持不变。
- 浏览器测试验证普通双击替换现有编辑区、Shift + 双击追加，以及属性面板与编辑区双向替换。
