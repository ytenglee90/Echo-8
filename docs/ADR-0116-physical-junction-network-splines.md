# ADR-0116：物理中转网络与连续样条规划

## 状态

已采纳，2026-11-04。用户同意重设整组连线路由，同时要求清理此前相关实现。本决策替代 ADR-0112、0113、0114、0115 的几何算法；这些文档只保留操作链与兼容性历史。

## 问题

独立分段加有向均值、反向手柄回退等迭代实现，无法在删除、重接、左右换位后稳定保证平滑；绘制、预览和重接还存在重复方向推断。逻辑关系的 from/to 不等于中转点的物理左右。多条线不能简单地要求所有逻辑输入/输出导数相等，尤其是全部端点在同一侧时。

## 新的边界

- `routing.ts`：投影真实端口，收集物理邻域；每个中转点只规划一次，给每条实际边附加可重建 RoutePlan。箭头所属端仍按现有标题/正文规则决定。
- `junction-routing.ts`：按点中心和实际端口划分物理半区，统一规划公共轴和短过渡区；不读取创建时分支方向、不读取持久私有状态。单侧为扇形，多侧共享轴线。15° 字段作为偏好，投影到保持平滑的可行方向，不能直接生成反向手柄。
- `route-geometry.ts`：只接收坐标、方向和过渡长度。开放三次 B 样条经精确插结转换为 Bézier spans，内部 C2；端部三控制点共线，公共短主干和端口引导段以同向切线、零曲率连接（几何 G2）。普通跨度使用靠近端点的局部过渡结点，使弯曲展开；横向重叠的窄端口使用有序绕行通道，避免接近的去程、回程自交。重合端点生成零长度路径，不生成小环。
- `connection-scene.ts`：新建、自由拖动、悬停和箭头重接的唯一预览规划入口。自由指针使用独立临时边，不改变已有图；悬停目标投影候选图，重复边不重复计权。组件拥有的有界缓存复用文档计划及同目标结果，不保留跨文档或全局缓存。
- `rendering.ts` 和图层：消费计划做绘制、长度中点、边界、命中、框选；不再求解中转曲线。箭头在真实直线端口段截取，不再移动样条控制点补箭头。

原持久指令、拥有者校验、标准事务和撤销路径不变。没有插件间实现导入或 UI 直接写入。主干与分支仍是独立的连接实体，选中、删除、重接、颜色、标签和复制边界保留；不展开为所有输入/输出的组合，规模为 O(E)。绘制的少量共享过渡重合不改变连接身份。

## 清理与兼容

移除旧 `junctionRenderPoint`、有向均值/符号回退、独立 smoothRoutingSegments 以及图层中的虚拟节点、任意关联切线、自由/重接几何备用算法。普通节点间原有标题同侧与正文路由保持原入口。

RoutePlan 仅在连线拥有者的重建几何中，不进入文档、文件、剪贴板或历史。选择几何修订包含计划 key，关联分支改变过渡区时命中缓存正确失效。原角度值不重写；不满足平滑的偏好被投影，旧文件打开即使用新规划。无新增公开消息或持久字段；connections dataVersion 11、剪贴板 schema 6 和文件容器不变，无数据库迁移。

## 验证

数学回归检查每条样条的非零前向切线、接缝切向一致、曲率连续和端部零曲率；多进多出保持边数为 E；逐条反转历史关系不改变物理路径；窄、宽、重叠、同侧、角度偏好及近重合端口检查自交。378 组端口边界场景保留为正式回归，24 组拥有者操作链继续覆盖合并、删主干/分支、重新连接、撤销/重做、跨侧移动及保存重开。

Chromium 验证完整用户操作链、多进多出分支独立删除、左右拖线、文本框和群组接入、箭头重接、方向偏好和实际渲染截图。按用户偏好只使用 Chromium，发布后只做定向轻量复查；单 HTML 从源码重新生成并通过 file:// 启动门禁。

本机 2,000 边样本：物理投影与样条规划约 16ms，绘制数据和标签中点约 34ms；缓存后的 100 次自由预览约 3ms。无新增逐段 DOM、插件或依赖。
