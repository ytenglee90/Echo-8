# ADR-0139 · 后台同步排队与 AI 失败恢复

## 问题与处理

快捷键和保存偏好的一秒防抖回调可能与 cloud-sync 自己尚未结束的网络指令重叠。普通 dispatch 会因插件当前指令仍占用串行队列而同步抛错，Promise.catch 无法接住这个同步异常。

核心的非等待式 `commands.defer` 现在同时允许已声明的后台跟进工作：有父消息时保留因果链，没有父消息时建立普通根消息，统一在当前串行队列之后执行。权限、深度、队列上限、生命周期和错误诊断不变。`invoke` 仍仅限活动正式指令，普通嵌套 dispatch 仍快速拒绝。cloud-sync 的两处防抖回调使用 defer，不内联执行同步事务。该扩展不增加文档命令或书籍数据版本。

画布计划在模型生成阶段进行结构校验，未截断的无效格式最多向原连接纠正一次，保留本次目录与权限；纠正也失败则进入可重试错误态。没有扩大对象范围、执行模型脚本或自动应用计划。控制说明增加完整 JSON 示例，避免混入文件导出协议。网络成功但计划准入失败时清理已完成任务，避免“当前内容仍在处理中”阻止重试；迟到的旧任务失败不能清理新任务。

Google 原生请求以用户选中的模型字段为准，既支持根地址、版本地址，也支持模型和完整方法地址。切换模型会替换 URL 中的旧模型，流式与非流式方法以及 alt=sse 同步调整。模型字段兼容官方的 models/ 前缀。404 不进行瞬时故障重试，并提示检查账号可用模型及保存连接。

Gemini 新建连接默认改为 `gemini-3.5-flash-lite`，现有用户连接保持原选择。2026-11-13 查阅的 [Google 官方弃用说明](https://ai.google.dev/gemini-api/docs/deprecations) 指出 2.5 Flash/Pro 已仅向过去使用过的用户开放；当前 2.5 Flash 的 404 不能仅凭 HTTP 状态断定具体账号原因。Google 的 [模型目录](https://ai.google.dev/gemini-api/docs/models) 与 [模型查询接口](https://ai.google.dev/api/models) 是可用名称与账号访问的核对来源。不在后台自动替换用户模型或真实调用用户 API Key。

## 验证

定向合同测试验证后台回调空闲/忙碌两种排队、正式指令完成后才执行、Google 地址与方法矩阵及 404 单次请求。浏览器从真实 UI 复现长云请求与快捷键防抖重叠，核对远端快捷键更新且没有 pageerror；验证 Gemini 404 后更换模型重试、一次格式纠正、连续格式失败后重试、范围准入失败后重试，以及原有节点编辑、审查、应用、撤销和保存重开。模型及云端使用隔离模拟接口。

文档、数据库和原生 `.e8` 格式均不需要迁移。便携 HTML 从源码重新构建。
