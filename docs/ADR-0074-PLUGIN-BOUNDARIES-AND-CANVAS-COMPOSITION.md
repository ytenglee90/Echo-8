# ADR-0074：插件边界、画布组合与运行时资源归属

## 状态

已采纳 — 2026-10-16。补充 ADR-0001、ADR-0025、ADR-0029、ADR-0032、ADR-0045、ADR-0060 和 ADR-0062；仅替代 ADR-0062 中把文本统计实现放在 `src/core` 的目录决定，不改变其 Unicode 统计语义。

## 问题

应用已经具备微内核、事务、能力与热停机机制，但若干实现边界仍然含混：画布插件直接渲染文本节点，单一内容目录提供者会被默认选中，插件可以持有未登记的计时器或文件句柄，交互结束缺少 owner/session 校验，插件中心暴露内部标识而没有解释依赖，托管浏览器测试还可以通过禁用 Worker 绕过真实后台路径。界面上，右侧编辑器与浮动面板也可能覆盖当前工作对象。

这些问题不会立即破坏正常路径，却会让新增内容类型、热停机和第三方插件逐渐退化为隐式耦合。

## 决定

1. 插件按“独立生命周期、状态所有权和协议边界”划分，不按 React 组件数量拆分。一个插件内部可以保留多个私有模块；没有独立生命周期的 AI 子视图不伪装成插件。
2. 画布插件只拥有相机、视口、通用指针手势、框选和受管插槽。文本节点插件通过 `canvas.entities` 与 `canvas.empty` 插槽提供节点层和空状态；画布不再导入文本节点实现。节点 CSS 以贡献根为作用域，热停机后不再泄漏样式。
3. 视图通过 `requestAll('content.catalog@2')` 合并所有活动内容目录提供者。只有恰好一个提供者时才使用增量版本；多个提供者每次按完整快照重新组合，避免“第一个提供者获胜”。
4. 插件上下文提供内核登记的 `resources.track/timeout/interval`。普通计时器、监听器、文件或其他外部句柄必须形成 owner lease；暂停、停止、卸载和启动失败均由资源注册表兜底释放。
5. 全局交互状态记录 `mode + owner + sessionId`。只有创建该会话的插件可以结束它，陈旧手势 token 不能终止较新的交互。
6. 插件注册命令或查询时若省略运行时 validator，该消息被解释为严格的无载荷协议，只接受 `undefined`，不再等价于接受任意输入。
7. 插件中心按核心组件、可选功能、AI/同步服务、管理与诊断分组。核心组件不可关闭；被活动消费者依赖的提供者仍显示在自己的服务分组，但开关禁用并列出可读的阻塞插件名称。内部资源数、权限数组和 owner ID 不作为普通用户界面信息。
8. 浮动面板将可见右栏作为布局边界并在栏宽变化时重新约束位置。编辑器打开或替换文本后，通过公开 `canvas.focusEntity` 命令在布局稳定后重新定位对应节点，使工作对象保留在剩余画布视口中。
9. 托管构建使用 Vite 识别的 `new Worker(new URL(...), { type: 'module' })` 入口。Vite 8 为 Worker 内受控 Blob 模块导入注入页面 HMR 客户端的开发期缺陷，由仅匹配该 Worker 模块 referrer 的最小 `injectQuery` 开发桥接隔离；普通页面 HMR 与生产输出不受影响。开发、E2E、性能与跨浏览器配置不再设置禁用后台 Worker 的环境变量。Worker 构造只存在于应用 composition root，插件仍只能由内核 `WorkerService` 调度，不能直接构造 Worker。
10. Unicode 文本统计仍是单一共享实现，但其目录从 headless 微内核移至 `src/services/text-metrics.ts`。核心协调层不承载文本业务规则。

## 结果

- 新内容类型可以独立提供目录和画布层，无需修改画布插件。
- 热停机能同时撤销命令、能力、UI、计时器和文件句柄；跨插件的陈旧 pointer-up 不会关闭别人的交互。
- 插件中心呈现的是用户可理解的生命周期与依赖关系，而不是内部调试数据。
- 托管测试现在覆盖与生产一致的后台 Worker 启动路径；便携构建仍由同一模块源生成。
- 新增两个普通内容提供者时会增加一次完整目录合并成本。该成本只在多提供者失效时发生，换取确定性组合和正确边界；单提供者继续走增量路径。

## 验证

- 架构测试继续禁止 feature-to-feature 实现导入，并验证 headless model 不加载 React 视图。
- 契约测试覆盖多内容提供者合并、无载荷消息拒绝、owner/session 交互结束、资源热停机与可读依赖阻塞。
- 浏览器测试在真实 Worker 路径下覆盖托管启动、编辑器/浮动面板共存、插件中心和画布交互。
- 发布门禁执行类型检查、Lint、全部单元/契约测试、托管 E2E、真实浏览器性能门禁、便携构建和 `file://` 便携测试。
