# ADR-0047：整画布导出绑定、AI 输出纪律与跨浏览器编辑同步

## 状态

已接受。

## 问题

整画布逐节点导出只完成一次外部写入，没有留下节点与目录文件的会话绑定，因此后续自动导出不能覆盖这些文件，标题变化也不能同步文件名。部分推理模型只返回 reasoning 字段或把 `<think>` 放进回答流，旧兼容分支会把思考误当最终答案。不同浏览器对 `contenteditable` 的原生撤销时机不同，也可能使浏览器私有历史与 Echo-8 全局历史竞争。持久化的 File System Access 句柄在重新启动时若直接读取，会触发浏览器权限提示，并在 `file://` 唯一来源下产生噪声错误。

## 决定

1. 首次整画布导出仍不得覆盖目录中未知的同名文件。成功后，导入导出插件为每个节点记录会话级目录、实际文件名、文件句柄、正文修订和标题。再次选择同一目录或自动保存时覆盖已确认的绑定文件。
2. 标题变化后，目录导出先写完新的安全文件名，再删除旧文件；删除暂时失败时保留待清理文件名并在以后自动保存时重试。该绑定不进入画布文件、历史或跨会话持久化。
3. 普通 AI 问答使用按任务复杂度分级的默认输出预算；明确长文任务保留更大预算。系统提示要求结论/成品优先、普通问题简洁、禁止展示内部思考。Prompt 策略能力仍可显式覆盖默认预算。
4. answer 与 reasoning 始终是不同通道。流式回答中的 `<think>`/`<analysis>` 即使跨网络分块也转入 reasoning；reasoning 显示最多保留有限字符。模型只有 reasoning 而没有 answer 时视为失败并提示重试，不得再把内部思考提升为用户答案。本条取代 ADR-0036 第 9 条的 reasoning-only 提升兼容分支。
5. 编辑区捕获 Ctrl/Command+Z、Ctrl/Command+Shift+Z 与 Ctrl/Command+Y 后，只广播全局 `history.undo`/`history.redo`，阻止浏览器建立第二套 contenteditable 历史。历史提交后编辑器接受权威修订，即使撤销使修订号下降，也不得把旧本地缓存误判成更新版本。
6. 画布和群组图层用生命周期内注册、明确 `{ passive: false }` 的元素级 wheel 监听处理缩放，并在卸载时清理，避免被动监听中的 `preventDefault` 警告。
7. 从 IndexedDB 恢复外部文件或目录句柄时，只调用不会弹窗的 `queryPermission`。只有状态已经是 `granted` 才恢复后台写入绑定；`prompt` 或 `denied` 状态等待用户通过明确的绑定/导入操作重新授权。AI 连接仍从个人 IndexedDB 数据恢复，启动时不再读取备份 TXT。

## 结果

- 整画布 TXT 可按自动保存间隔覆盖，标题改名可同步目录文件名，同时不误覆盖首次遇到的外部同名文件。
- 简单问题更快到达重点，思考不会进入正式回答和记忆原文。
- Chromium 与 WebKit 的编辑撤销都走同一条全局历史，撤销后可以继续输入而不会出现正文版本竞态。
- 单文件 `file://` 启动不再主动触碰旧文件句柄，也不再因为画布缩放产生被动滚轮监听警告。

## 验证

定向测试覆盖整画布覆盖/改名/旧名清理、reasoning-only 拒绝、跨分块思考标签分离、AI 输出预算、持久句柄无提示检查、编辑区撤销/重做后继续输入，以及单文件滚轮缩放无控制台错误。
