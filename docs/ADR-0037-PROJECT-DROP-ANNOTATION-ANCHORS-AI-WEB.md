# ADR-0037: 项目拖入、注释屏幕锚点与 AI 原生联网

## 状态

Accepted

## 背景

画布已经能从文件面板打开 `.echo8`，但把项目文件拖进画布时仍被普通文档导入逻辑忽略。注释模型保存的是耐久文字锚点或目标实体，首次打开输入框还需要一个仅属于本次界面的屏幕锚点。AI 模型配置允许任意模型字符串，但原界面没有明确表达这一点；联网搜索也不能仅靠 Prompt 假装存在，必须由模型平台实际提供。

## 决定

1. 画布视图只识别 Echo-8 项目文件并广播 `file.openProject`；解析、校验、打开前恢复点和文档替换仍完全由文件插件与核心边界负责。读取兼容 `.echo8` 和常见误写 `.eco8`，新保存文件始终使用正式 `.echo8` 扩展名。
2. `editor.selection@1` 可以附带编辑器拥有的 viewport `screenAnchor`。画布通过 `canvas.viewport@1` 暴露已挂载视图的尺寸和可选屏幕原点。注释插件结合公开的选择、内容几何、群组和相机能力计算首次弹窗位置；屏幕锚点只进入 workspace 打开状态，不进入注释正文或全局历史。
3. AI 模型输入框是自由文本并提供可选建议，不将建议列表当作白名单。模型 ID 原样通过配置验证和提供者请求发送。
4. 联网开关属于单个 `AIAssistantInstanceState`，保存在 workspace/personal session settings，默认关闭，新建独立助手不继承。准备上下文时把该值冻结进 `AIPreparedContext`，生成途中切换开关不会改变已经发出的请求。
5. `AIGenerateRequest.webSearch` 只能触发经过 Echo-8 明确适配的模型平台原生能力：Gemini GenerateContent 的 Google Search grounding、阿里云百炼兼容接口的 `enable_search`，以及 OpenAI Chat Completions 当前 `gpt-5-search-api` 的 `web_search_options`。其他连接在联网开启时必须在发出网络请求前失败并给出清楚说明，禁止静默退化为“假联网”。
6. `.echo8` 在应用内使用专属项目图标。纯 HTML 网页不能为 Windows/macOS 文件管理器注册系统级扩展名图标；真正的桌面文件图标留给未来安装包、PWA 文件处理器或桌面壳完成，当前不修改系统文件关联。

## 结果

- 文件拖入和按钮打开共用同一条公开打开指令与恢复流程。
- 新注释输入框紧邻实际光标或选中画布目标，不再沿用上一次浮窗位置。
- 用户可以直接填写平台控制台给出的新模型 ID，同时仍能从常用建议中选择。
- 联网状态不会跨助手串用，也不会伪装成模型本身不存在的能力。
- 项目格式版本、撤销协议和现有文档数据均不变，不需要数据迁移。
