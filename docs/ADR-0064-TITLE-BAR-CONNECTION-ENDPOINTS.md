# ADR-0064：标题栏连接端点

## 状态

已采纳；控制点的纵向扇出部分由 ADR-0065 的水平端点切线决定替代，其余决定继续有效。

## 问题

原有连线只允许左右入口，并在节点移动或缩放后根据两个节点的水平中心重新决定左右端点。纵向排列多个节点时，连线集中在正文中部，不适合表达从多个上级节点汇入同一标题的关系。仅在标题栏增加一个透明按钮并不够：现有创建命令、查询和渲染都会把端点重新覆盖为 `left` 或 `right`，保存、撤销或复制后也无法保留标题栏语义。

## 决定

1. `ConnectionSide` 增加 `title`。标题栏圆点前方提供独立拖拽入口；从该入口开始的连接将双方端点都规范化为 `title`。
2. 普通左、右入口和顶部工具创建的连接仍使用原有的水平中心自动路由。旧书籍的 `left`、`right` 记录行为不变。
3. `title` 端点固定在节点左边界、标题栏 42px 高度的垂直中点。入口保持为无标记的透明热区，不在节点外增加常驻或聚焦圆点。标题连线使用一条紧凑的三次贝塞尔曲线；外扩幅度随端点跨度缓慢递增，纵向控制点使共享端点的多条线从端点开始自然扇开，避免在中途挤成明显交叉点。目标端使用随画布背景自动对比的箭头，选中与悬停时箭头和线条同步使用更强的选择色。预览、命中测试、空间索引和框选使用同一组控制点与边界。
4. 创建操作仍通过 `connection.create` 命令进入连接插件的单一事务，拖拽过程仍是 `connection.draft.preview` 临时信号。连线创建只产生一条全局历史记录。
5. 连接插件文档数据版本从 1 升到 2，并提供结构不变的 `1 -> 2` 迁移。容器格式保持 version 2。内部剪贴板仍为 bundle version 1；其连接片段验证器接受新增端点值，因此同版本应用内复制粘贴完整保留标题连接。
6. 标题连线同时注册独立的 `connection.toggleTitleSelected` 操作，默认快捷键为 `Shift+L`。它要求恰好选中两个文字节点：没有连线时创建标题到标题连线，已有普通连线时原位转换并保留文字与尺寸，已有标题连线时断开。操作由连接插件拥有并通过一个标准事务进入历史；快捷键中心只读取统一动作与快捷键注册表，不另存一份功能清单。

## 兼容性

- 旧书籍可以迁移，所有旧连线继续自动选择左右端点。
- 新版标题连接在新版中可保存、恢复、复制、撤销和重做。
- 旧版应用读取新版连接命名空间时不保证理解 `title`；新版书籍通过插件 `dataVersion: 2` 明确声明这一能力，不伪装成旧数据。
- `connections.list@1` 和 `connection.create` 的外层消息形状不变，只扩展端点枚举。

## 验证

- 纯函数测试覆盖标题锚点、拖拽目标规范化、紧凑的左侧贝塞尔曲线和包围盒。
- 连接合同测试覆盖移动后端点稳定、标题快捷操作的创建/转换/断开，以及撤销和重做。
- Chromium 交互测试从真实标题栏入口拖拽，核对隐藏热区、SVG 起止坐标、目标端箭头和左侧曲线外扩，并验证全局撤销、重做。
- 完整单元、视觉、托管浏览器和 `file://` 单文件回归继续作为发布门禁。
