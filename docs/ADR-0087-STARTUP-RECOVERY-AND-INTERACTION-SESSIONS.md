# ADR-0087：启动恢复通道与交互会话令牌

状态：已采纳（2026-10-31）。补充 ADR-0006、0035、0045、0046、0081、0086。

## 背景

浏览器本机恢复数据可能在写入中断、旧版本迁移或正文分块损坏后无法通过启动校验。原有启动保护页只说明内核没有进入不完整状态，却没有给用户继续工作的入口，也没有区分“暂时绕过恢复数据”和“永久删除损坏恢复数据”。此外，高密度画布在全选后快速连续拖动画布时，旧的异步 `interaction.end` 可能晚于下一次 `interaction.begin` 到达，造成 `panning -> panning` 非法转换，随后空白点击也无法恢复正常选择状态。

## 决定

1. 启动策略增加 `memory-only`。该模式不打开 IndexedDB，不读取、覆盖或清理本机快照、日志、恢复点和正文块；界面必须持续显示安全模式提示。
2. 启动失败页提供三条明确路径：普通重试；保留恢复数据的安全进入；经过二次确认后清理本机恢复会话并重试。清理只删除 `snapshots`、`journal`、`recovery`、`contentChunks`，保留个人设置元数据和个人文本资源，也不影响用户已经保存的 `.echo8` 文件。
3. 安全进入状态通过显式 URL 查询参数传递，只作为本次页面启动输入；不得绕过受治理持久化边界写入 `localStorage` 或 `sessionStorage`。
4. 指针交互的开始、结束和取消必须携带同一个不可复用会话令牌。结束消息必须先进入串行命令队列，再提交该次相机状态；新指针会话不得复用上一会话的结束消息。
5. 插件退役字段清理由数据所有者注册幂等 scrubber。核心可以遍历快照、历史、日志和恢复点，但不得识别 `textNode`、`editor`、`aiProposals`、`clipboard` 等私有结构。

## 验证

- 浏览器测试注入正文块长度不一致的本机快照，验证失败页、安全进入不改写损坏快照、退出安全模式再次触发保护，以及二次确认后恢复正常启动。
- 极端画布测试在 2,000 个节点全选后连续执行两次平移，确认没有非法交互转换，并验证切回选择工具后空白点击可清空选择。
- 架构测试继续禁止未治理浏览器存储，并检查内置命令、查询和能力名称只能从协议注册表消费。

## 影响

安全模式可能暂时看不到浏览器中的未保存会话，但它不会破坏该会话，用户可以先打开已保存文件另存。只有明确确认的清理操作具有破坏性。交互会话令牌增加了少量消息元数据，却消除了依赖 Promise 完成时序的隐式状态耦合。
