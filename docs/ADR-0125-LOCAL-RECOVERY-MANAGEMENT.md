# ADR-0125：本机恢复副本管理与可选数量限制

日期：2026-11-05。状态：有效；补充 ADR-0124 的本地维护策略。

## 问题与归属

ADR-0124 的安全清理只删除已备份且重复的恢复副本，独有版本可能持续累积。用户需要明确查看和删除历史版本，同时保留当前书籍、撤销历史、个人设置及待上传数据。

UI 由 import-export 插件拥有，IndexedDB 生命周期和清理由 core.persistence 强制服务拥有。所有操作通过公开消息路由、运行时校验、插件声明与串行命令队列进入持久化写入队列，视图不直接访问数据库。

## 版本化协议

- `system.recovery.catalog@1`：只读目录，返回总数、查询时刻、可选数量上限，每页最多 30 条摘要、记录估算字节和下一页游标。现有 ID 的时间前缀支持按键倒序分页；目录不还原正文，不同时载入全部历史快照。大小不包含共享正文块，不等于实际可释放空间。
- `system.recovery.delete@1`：删除指定的非空 ID 批次（最多 1000 项），或删除查询时刻及以前的全部恢复副本；两种选择互斥。删除不存在的 ID 是幂等操作。删除恢复记录使用一个 IndexedDB 事务，成功后回收不再被引用的正文块并刷新计数。
- `system.recovery.setRetention@1`：设置 `null`（默认不限制）或 8/20/50/100，启用时立即整理，后续创建恢复点和检查点时继续执行。限制覆盖手动恢复点，较新的副本优先。

删除与更改数量限制前，UI 展示具体影响，用户可取消。清空以目录查询时刻为界，不扩大到之后生成的版本。删除不可撤销，属于本机持久化维护，不进入书籍的文档补丁历史；否则删除副本本身会又成为必须永久保存的历史备份。这与既有 `system.storage.cleanup` 的维护边界一致。

任何显式删除或数量策略更改，先完成当前文档及历史的本机检查点。检查点失败则不开始操作。正文垃圾回收继续保护最新快照、保留的恢复副本及日志正逆补丁；不清空 snapshots、journal、personalAssets、meta，也不调用云端删除或本地文件覆盖。

## 兼容和迁移

`.echo8` 格式、IndexedDB v5 结构、旧的恢复目录/预览/恢复指令和安全清理协议不变。唯一新增设备设置位于 `meta/recovery-retention-limit-v1`，旧数据缺少该键或值无效时惰性解释为 `null`，不删除原有独有副本。关闭限制保留现有副本。没有用户启用限制时，继续沿用 ADR-0124 的保护策略。

## 验证

协议测试覆盖无效/歧义删除负载、无效数量及新旧查询并存。Chromium 回归覆盖单条删除、取消、批量删除、清空、刷新后当前文档和撤销/重做、旧数据分页、限制的显式启用/取消、创建后的数量控制、重启保留设置及关闭限制。原有安全清理保护测试继续保留。便携 HTML 从源码构建，通过真实 file:// 启动和操作验证。

2026-11-05 本次验证：类型检查、lint、525 项单元测试通过；恢复管理与云存储定向 6 项通过；便携版 file:// 2 项通过。全量 Chromium 使用独立输出目录、4 个 worker 运行，162 项通过、24 项失败；失败集中于连线几何/中转点交互、颜色预设断言和既有界面截图，不包含新增恢复管理用例。未修改这些测试的期望值或连线/颜色实现，不能将本次结果视为全量浏览器回归通过。实际界面已截图检查，单 HTML 已重新构建；未发布线上服务。
