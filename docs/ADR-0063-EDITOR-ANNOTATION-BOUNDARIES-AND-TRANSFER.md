# ADR-0063：编辑器注释边界、剪贴板传递与视图稳定性

## 状态

已采纳。

## 问题

文本注释以 UTF-16 偏移保存，但偏移恰好处于一次插入的起点时，旧规则会把注释连同新输入一起向右推。这样，在正文末尾添加注释后继续输入，注释会错误地跟随新文字。浏览器原生复制、剪切只携带纯文本，拖放重绘又可能让原生拖动态滞留，导致注释丢失或编辑区不再接受输入。

内容投影重建和浮层关闭后的焦点恢复也只恢复 DOM 焦点，没有恢复编辑器拥有的滚动位置与文本选区；沉浸写作中的换行、删除和关闭注释因此可能改变视口或把光标放到正文开头。

## 决定

1. 文本注释是字符间的点，并归属于它左侧的字符。插入发生在注释点本身时，注释不移动；插入发生在它之前时，注释随旧正文右移。
2. 删除或替换半开正文范围 `[start, end)` 时，属于被删字符的注释点范围是 `(start, end]`。这些注释与正文在同一事务中删除；撤销同时恢复。移动正文范围时，同样用 `(start, end]` 判定随正文移动的注释。
3. 编辑器复制或剪切正文时，系统剪贴板继续写入标准 `text/plain`，并额外写入有版本、有限额的 Echo-8 注释 MIME 数据。浏览器不保留自定义 MIME 时，编辑器可在同一运行会话内使用最多保留两分钟的内存副本；只有纯文本完全匹配时才接受。外部应用仍只接收纯文本。
4. `content.applyDelta` 可携带经过验证的相对注释副本。文本所有者请求 `content.annotationClonePlan@1`，把提供器返回的 owner-labelled patches 与正文、格式、普通锚点变换一次提交。复制产生新注释 ID；剪切先由普通范围删除语义移除原注释，再由粘贴事务创建副本。
5. 注释剪贴板最多携带 256 条注释和合计 1,000,000 个 UTF-16 正文单元；单条注释仍受 200,000 单元上限约束。不可信自定义 MIME 在编辑器、命令边界和注释提供器处分别校验。
6. 编辑器的滚动位置和失焦前文本选区属于临时视图状态。内容投影重建、受控输入、拖放和注释浮层归还焦点时恢复这些状态，不写入文档、工作区或历史。受控 drop 一经接管便立即释放原生拖动态，不能等待可能因 DOM 重建而缺失的 `dragend`。
7. 画布注释图标属于屏幕坐标浮层。每次相机预览把世界锚点换算为屏幕位置，并对 100% 以下的标记使用半强度缩放补偿：屏幕比例取画布缩放比例的平方根，因此 25px 基准圆形标记在 40% 画布缩放时约为 16px，而不是完全补偿后的 25px，也不是无补偿的 10px。100% 以上保持 25px 上限。位置始终跟随目标；该补偿是派生视图状态，不增加文档字段或历史记录。

## 兼容性

本决策不增加持久化字段，也不改变 `.echo8` 文件格式。现有注释记录继续使用 `text-range.offset`。没有 Echo-8 自定义 MIME 的剪贴板和拖放内容保持纯文本行为；未知或超限元数据被忽略。

`content.annotationClonePlan@1` 是新的可选能力。注释插件未启用时正文仍可正常粘贴，只是不产生注释副本。

## 验证

- 契约测试覆盖注释点左右插入、范围删除、移动、克隆和全局撤销。
- 编辑器单元测试覆盖边界归属、剪贴板编码、文本匹配和恶意元数据拒绝。
- 浏览器测试覆盖沉浸模式换行/删除滚动稳定、关闭注释后的光标恢复、带注释拖放、复制/剪切粘贴，以及画布注释图标在 100% 与 40% 缩放下遵循柔和补偿比例。
- 类型检查、Lint、单元测试、浏览器测试和便携构建继续作为发布门禁。
