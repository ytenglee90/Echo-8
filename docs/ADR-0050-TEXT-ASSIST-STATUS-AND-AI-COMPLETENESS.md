# ADR-0050：纠错资源状态与 AI 回答完整性控制

## 状态

已接受。

## 问题

纠错插件把“补充内置规则”和“修复规则”暴露为普通用户操作，容易让用户误以为日常使用前必须反复维护，同时格式栏只显示开关，无法判断规则是否真正完成编译。AI 侧虽然已将 answer 与 reasoning 分离，但部分推理模型会让思考过程占用单次输出额度；平台达到长度上限时，如果应用不读取结束原因，最终答案会被当作正常完成。按单个对话轮次读取历史也可能把用户问题与对应回答拆开，破坏语境。

## 决定

1. `textAssist.ensureResources` 与 `textAssist.mergeDefaultRules` 保留为插件内部维护指令，继续接受启动、打开文件和资源变化事件驱动，但退出命令面板和快捷键中心。公开给用户的只保留纠错/补全开关、打开规则和从 TXT 更新规则。
2. `text.assist.resources@3` 的 `ready` 只有在绑定存在、当前资源不脏且没有退回上一有效版本时才为真。资源变化后立即广播“加载中”，并由内核任务调度器后台重编译。
3. 格式栏纠错图标显示资源状态点，工具提示提供“已加载条数、加载中、未导入、沿用上一有效版本”等文字说明。
4. AI 提供者把 OpenAI 兼容接口和 Gemini 的结束原因统一为 `stop`、`length`、`content-filter`、`tool-calls` 或 `other`，通过既有生成结果与流式完成事件向助手报告。该字段为向后兼容的可选协议字段。
5. 助手按任务复杂度保留更实际的最终输出预算。若结束原因为 `length`，或兼容接口未报告原因但实际输出令牌已接近请求上限，助手自动执行一次有界断点续写；续写要求只补齐未完成答案，并在合并时去除重复衔接文本。再次达到上限时明确提示用户，而不是伪装成完整答案。
6. 可见和持久化的 reasoning 仍与 answer 分离，最多保留 800 个字符，只作为可折叠辅助信息，永远不进入记忆证据。系统提示要求先给结论或成品、压缩非必要推理，但不声称能控制所有第三方模型的内部推理算法。
7. 记忆命中对话时优先读取一个完整的“用户问题＋助手回答”交换；只有整组放不进预算时才退回单轮或其他自然边界。模型侧检索报告只保留选定范围、实际原文数量、未覆盖和被推迟资料，不再注入内部批次参数。
8. 当前记忆名称进入 AI 浮动面板标题，原来的正文上方提示删除。Prompt 模板使用独立的模板图标，不再复用全局设置齿轮。

## 边界

- 自动续写最多一次，避免第三方接口异常时形成无界请求或费用循环。
- 思考显示截断不修改提供者已经产生的网络用量；真正减少推理成本仍取决于平台是否支持可靠的推理强度参数。
- 续写和合并发生在 AI 任务内部，只有合并后的完整结果通过 `ai.generation.record` 进入对话正文；中间片段不进入历史、保存或记忆。
- 不修改 `.echo8` 文件格式、正文格式或撤销记录格式。

## 验证

- 算法测试覆盖结束原因传递、缺失结束原因的长度推断、断点续写请求、重叠合并、问答交换边界和输出预算。
- 内核契约测试验证规则状态完成后才为 ready，维护动作不再注册为公开 UI 操作，并验证 SSE 结束原因归一化。
- 浏览器回归验证当前记忆显示在标题、正文上方旧提示消失，以及 Prompt 模板按钮使用独立图标。
