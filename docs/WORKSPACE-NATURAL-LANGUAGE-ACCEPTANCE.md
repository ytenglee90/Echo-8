# 全工作区自然语言同义指令验收

验收工具从真实助手入口测量其自然语言行为。语料只供验收工具读取。优化后复用最初的 528 条原句，比较完全通过的意图和逐句的实际结果。编辑器相关的 33 条原句复查用双击打开真实窗格，在其他互斥面板打开前记录状态。群组聚焦增加了最终边框位置、倍率和存盘坐标的独立核对。

## 范围与入口

当前运行时目录包含143个执行适配、22个额外界面入口；另测11个组合场景。每项3种说法，共528条。`language-e2e/corpus.ts` 对执行适配做缺项检查，`scripts/probe-workspace-language.mjs` 从真实界面读取运行时目录；报告分别列出目录缺项与语料执行情况。

运行：

```powershell
pnpm run test:workspace-language
```

新增动作使用独立扩展语料：

```powershell
$env:ECHO8_LANGUAGE_SUITE='extended'
pnpm run test:workspace-language
Remove-Item Env:ECHO8_LANGUAGE_SUITE
```

扩展报告单独命名为 `Echo-8-扩展动作同义指令测试报告`，不会改动原来 528 条或替换其报告。两个集合共同检查运行时动作是否缺少语料，各自报告明确列出属于另一套的动作。新增“明确对象及内部关系复制到右侧”通过导出的实际书籍检查原对象记录、正文、位置、内部连线及原连线，而不是只检查助手回答。

缺少本地缓存资产会直接报错，不下载模型。只有全部业务结果经实际状态核验通过，验收命令才返回成功；采集正常结束不代表助手通过验收。调试时可设置 `ECHO8_LANGUAGE_FILTER` 为逗号分隔的动作ID，这种运行属于部分语料，不能称全覆盖。

## 方法

1. 每条原句使用新的浏览器上下文与隔离书籍，防止前一条操作影响后一条。
2. 通过正式命令准备选区、剪贴板、恢复点和编辑窗格等前置。
3. 从真实助手输入框发送完整原句，不传入期望计划，不伪造意图、模型向量或生成结果。
4. 记录助手自己的答复、状态和可见界面。明确请求执行的文档预览可经所属面板应用；请求“先预览”的场景保留待确认状态。
5. 通过公开只读能力或实际导出的书籍、TXT、DOCX核对结果。后置固定计划只读取状态与导出检查文件，不执行待测意图。
6. 同一动作的三种说法独立判定，分别记录是否全部通过、是否换说法失效，以及具体失败类型。

局部调色的模态面板先记录实际可见状态，再正常按 Esc 关闭，随后进行只读快照导出，避免面板遮挡验收按钮。此调整不改变原句和原判定标准。对话存档另有共享浏览器定向回归：等待提交回执后打开真实存档原文，核对先前输入；原语料中缺少独立断言的存档结果仍保留 `unverified`。

复制用例读回内部剪贴板里的卡片正文，核对复制目标身份和数量。选区竞争测试先捕获指令发送时的对象 ID，再改选另一张卡，检查剪贴板仍收到原卡而画布保留后来的选区。编辑器范围用例等到浏览器设置 DOM 选区后读回实际文字。测试语料原句不变。

所有外部与模型API请求均受拦截。BGE小模型、分词器与ONNX运行时由本地缓存提供真实字节；没有本地生成式模型，也没有以模拟回答代替它。报告中的资产加载次数只表示观察到相应加载，不表示已完成通用生成式规划。

## 判定边界

只有 `verified` 计入通过。`failed` 是实际对象、参数或状态不符；`unrecognized-or-misrouted` 是机械指令落入模型未配置或无法理解分支。无法独立证明的结果保留 `unverified`，不能为了凑覆盖率算成功。缺本地生成模型、缺授权夹具、入口无法发送、超时及读回失败都分别记录。

报告同时区分“已准备语料”“已尝试采集”“实际发送”和“结果核验”。此前进入书库会自动最小化全部助手，页面也缺少助手入口，三条返回画布消息未能发送。本轮保留已打开的助手和草稿，并增加书库助手入口，原来三条消息均已通过真实输入框发送并核验通过。

初次采集中，多编辑窗格造成工具栏按钮被遮挡；已改用正常键盘入口复查相关33条，不把测试准备错误计作助手误判。`scripts/review-workspace-language-results.mjs` 合并保存的完整采集与指定复查报告，可根据原始导出重新计算更严格的断言；不会重写原句、原始答复或文档证据。初始判断变化保存在 `initialVerdict`。
