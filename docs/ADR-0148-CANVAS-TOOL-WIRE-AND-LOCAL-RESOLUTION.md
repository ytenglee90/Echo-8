# ADR 0148 画布工具的模型请求与本地定位

状态为有效，补充 0147。

用户发送「武器卡内设计武器内容」后，DeepSeek 返回查询和读取正文两个工具请求。第二次实际请求仍使用应用内部的 `toolCalls` 和 `toolCallId`，因此服务无法按 Chat Completions 协议匹配工具结果。用户报告 HTTP 422，附件包含请求正文，未附接口响应详情。

AI 连接提供者在发送 OpenAI 兼容请求时，将工具调用转换为 `tool_calls` 内的 `type`、`function.name` 和 `function.arguments`，用 `tool_call_id` 匹配每一项结果。官方 DeepSeek 地址上的工具对话显式使用非思考模式，采用接口默认工具选择。该协议的思考模式要求完整传回历次 `reasoning_content`，应用的历史仅保存并发送面向用户的回答。其他兼容端点不发送 DeepSeek 扩展字段。AI 生成运行时遇到带工具结果的原生续轮返回 422 时，保留本轮请求及已取得的画布数据，切换到结构化信封重试一次。普通接口错误仍保留其错误状态。

本地规则对确定匹配仍直接走原有事务和审查。`canvasControl.localPlan@1` 的结果新增可选 `unresolvedTarget`。本地无可靠目标且当前连接可用时，交给模型查找真实对象并继续原任务。未配置模型时保持本地说明。已命中的歧义候选仍由原来的选择流程处理。用户明确让应用写入时，助手收到没有计划的纯文本最多纠正一次。普通对话的任意 JSON 不直接当作画布计划。

编号节点允许汉字和数字之间有无空格，重复命中时仍需消歧。常用编号列表、连到标题、在卡内写正文、无名称分组和按群组成员解组沿用已有计划。解组只删除群组对象。查找优先使用混合索引，索引提供者缺席时使用原有文本搜索能力，仍按允许范围筛选目标。

内部消息、画布文件与数据库沿用现有版本。协议验证使用模拟 DeepSeek 接口复现两条并行工具结果及实际正文写入，并覆盖续轮 422 兼容重试、口语分组及编号节点连线。
