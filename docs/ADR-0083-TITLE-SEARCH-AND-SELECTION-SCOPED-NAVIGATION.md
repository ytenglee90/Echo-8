# ADR-0083：标题检索与选中范围导航

## 状态

已采纳（2026-10-29）。补充 ADR-0003，并替代 ADR-0028 中“导航只限当前活动编辑区”的范围决定；ADR-0028 的串行命令队列纪律继续有效。

## 问题

查找替换原先只调用 `content.search@1` 扫描正文，因此节点标题无法命中。结果列表还维护一套只属于面板的临时选中状态，点击结果不会让画布节点显示真实选中提示。上一处／下一处依赖活动编辑区，既不能遍历多个选中的文字节点或文本框，也不能在没有编辑区时遍历全画布结果。

## 决定

1. 文本所有者新增 `content.search@2`。请求仍然按节点、按正文块扫描并受结果上限和取消信号约束，但结果明确携带 `field: title | body`。标题命中的偏移和修订属于节点标题；正文命中的偏移和修订继续属于分块正文。`content.search@1` 保留原有正文专用语义以兼容现有消费者。
2. `content.replacePlan@1` 保留正文专用语义以兼容旧消费者；文本所有者新增 `content.replacePlan@2` 接收标题与正文混合命中。标题命中先校验节点修订和原文范围，再检查替换后的全画布标题唯一性；若标题改变，文本所有者还会按原有最长标题关联规则同步正文引用。直接正文命中、标题关联同步和节点标题写入先合并成不重叠的范围替换，再作为一个标准补丁事务提交，因此一次撤销会同时恢复标题、正文和关联。
3. 结果列表的单击、组合键多选、框选和列表全选最终都分发公开的 `selection.set`／`selection.clear` 命令。拖动框选过程仍用可合并的 `search.selection.preview`，松开后只提交一次选择。搜索面板通过 `selection.changed` 同步列表状态，不再拥有一套与画布分离的权威选择。
4. 上一处／下一处第一次执行时读取 `selection.read@1`：若含一个或多个 `text-node`，以这些稳定 ID 作为本轮导航范围；否则使用本次全画布搜索的全部结果。导航为了精确反馈会把当前命中节点设为画布选择，但保留本轮最初的范围快照。用户从画布或结果列表重新选择后，快照失效并按新选择开始下一轮。
5. 导航命令仍只同步预留索引并立即退出串行命令队列。插件拥有的延迟任务随后分发 `selection.set`。命中正文时，它通过扩展后的公开 `editor.open` 请求在同一工作区事务中替换打开对应编辑区、切换大文本窗口并写入修订绑定的 `revealRequest`；不再要求目标预先是活动编辑区，也不经过会死锁的嵌套命令。命中标题时不打开正文编辑区，而是发布临时 `search.match.preview`，由文本节点所有者在画布标题的精确匹配范围绘制蓝色高亮。新搜索、重新选择或清除导航会清除此高亮。
6. 查找框的普通 Enter 立即重新分发 `search.run`，并取消尚未执行的防抖任务；Shift + Enter 保留多行输入。IME 组合期间不截获 Enter。

## 兼容性

不修改 `.echo8` 文件格式。新增的是版本化派生搜索能力、标题与正文替换计划能力、`editor.open` 的可选修订范围和临时导航字段。旧的 `content.search@1` 和正文专用 `content.replacePlan@1` 继续可用；新的 `content.replacePlan@2` 产生与其他文本写入一致的标准历史补丁。编辑器打开范围、搜索结果、标题高亮和导航范围都属于个人工作区或临时状态，不进入文档历史。

## 验证

- 内核测试验证标题偏移、旧正文替换能力拒绝标题命中，以及新能力在一次历史事务中替换标题、正文并同步标题关联。
- 纯函数测试验证单选、多选和无选择时的循环顺序。
- 插件测试验证多选范围在逐个高亮期间保持稳定，用户清除选择后恢复全画布范围。
- 浏览器测试验证标题可见、Enter 不插入换行、结果点击会触发画布真实选中提示、标题导航显示蓝色精确高亮，所选标题命中可直接替换，正文导航自动打开对应编辑区并选中文字。
