# ADR-0114：以中转点中心判定自由拖线左右

> 几何实现已由 [ADR-0116](ADR-0116-physical-junction-network-splines.md) 替代；本文保留为历史记录。

## 状态与问题

已采纳，2026-11-04，细化 ADR-0113。用户明确要求用鼠标相对中转点中心的位置划分拖线方向。自由指针参与已有图的共同切线计算时，已有节点全在同一侧、方向相反等布局会覆盖手势方向，导致跨过点中心仍从错误一侧出线，已有曲线也会随自由指针改变形状。

## 决定

自由新建中转点拖线用当前世界坐标 pointer.x 与 junction.x 比较，小于为左侧输入，大于或等于为右侧输出。预览在中转点使用面向该半区的局部水平手柄，并保留用户明确设置的 15° 旋转偏移；不把自由指针作为真实连接加入已有图，也不改变原曲线。上下位置只影响曲线形状，不参与左右分类。

悬停真实节点、文本框、群组或中转点后，继续使用现有候选拓扑、真实端点和公共切线计算；左右输入/输出的请求转换仍以最新鼠标坐标相对点中心判定。共享输入适配器的释放采样与连接图层的预览传入同一 pointer。未提供 pointer 的旧内部调用保留按真实锚点推断的兼容回退。箭头重接和非中转点起始手势不进入此分支。

自由预览仅为本地图层的可重建几何；既有临时广播、交互会话、取消、正式指令、拥有者校验、事务和撤销路径保持不变。没有新增消息或持久字段，connections dataVersion 11、剪贴板 schema 6 和用户文件不变，无迁移。

## 验证

先在 Chromium 复现已有节点全在左/右侧时的反向预览，再检查鼠标在点中心上下左右反复跨越，左侧没有自由端箭头、右侧有箭头，原曲线不变，Escape 不新增连接。纯协议测试覆盖目标中心/锚点与鼠标半区相反、中心边界及普通节点手势不受影响。保留实际接入节点、文本框、群组后的预览/提交一致和撤销检查，以及既有曲线布局、手动角度和单 HTML 启动回归。仅使用 Chromium，发布后做定向轻量复查。
