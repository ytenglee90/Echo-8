# ADR 0165 · 群组成员预览的冲突范围

有效，补充 ADR 0162、0163。无新指令、文件字段、数据库或协议版本迁移。

## 问题与证据

用户反馈模型已识别“空白1踢出群组1”，确认时却显示“计划引用的对象已变化”，本人没有移动对象。旧提示没有对象名或变化项，不能据此断言用户有操作，也不能仅凭截图确定当次变化来源。

复现确认一种过度拒绝：生成群组移出预览后，后台更新该节点的正文，即使群组及成员关系完全相同，旧检查仍比较正文修订、正文长度以及随正文更新的节点记录修订，因而拒绝移出。普通等待、独立对话节点追加和 60 成员群组中的正常移出没有复现错误。

## 决定

仅当模型计划的所有步骤均为已注册的 `group.add` 或 `group.remove` 时，预览对象检查忽略正文修订、正文长度和节点记录修订号，继续比较节点实际标题、位置、尺寸、颜色、显示形式及存在性。完整群组记录继续严格比较，成员列表、名称和群组修订变化仍拒绝；发送时选区检查保留。所有者继续拒绝无效成员、跨组加入及不存在的对象，真实写入和撤销仍由现有群组命令执行。

任何其他动作或混合计划继续使用完整正文及对象标记，不将此例外扩散到正文覆盖、删除、改名、布局或复合动作。成员操作不会读取、替换或回滚正文；其一次撤销只恢复本次群组变更，期间已完成的正文更新应保留。

真实冲突提示保留原错误前缀，增加对象名称和变化项，例如“节点「空白 1」（标题）”或“群组「新群组」（成员列表）”。只展示变化字段名称，不泄露正文或内部标记。身份绑定仍使用稳定 ID，展示编号不变成持久 ID。

## 验证

回归覆盖独立对话更新、目标正文更新、节点改名、群组成员改变；允许前两种，后两种拒绝且不产生部分写入。移出与一次撤销后验证正文不丢失。浏览器通过当前选中模型返回的稳定节点/群组 ID，测试 60 成员群组的移出与恢复，避免仅检查模型文字。
