# ADR-0062：统一命令类型表与 Unicode 统计实现

## 状态

已采纳。

## 问题

公开命令虽然在注册处标注了参数和返回值，但调用接口仍接受任意字符串、任意参数，并允许调用方通过 `dispatch<TResult>` 自行声称返回类型。命令名称、参数和返回值没有形成同一个编译期契约。

产品可见字符统计也存在多份实现：普通编辑、写作活动和分块正文各自创建 `Intl.Segmenter` 并解释空白字符。它们当时结果相近，但任何一处单独修改都会重新造成画布、编辑器和统计栏不一致。

## 决定

1. `src/protocols/commands.ts` 定义应用级 `ApplicationCommandMap`。拥有公共协议的模块通过 TypeScript 声明合并登记 `命令名 -> 参数 -> 返回值`，核心只依赖协议层，不导入插件实现。
2. `PluginContext.commands.dispatch/invoke/defer` 和 `ViewClient.dispatch` 从该表推导参数与返回值。已登记命令不能再由调用方传入任意返回泛型；参数不符合协议时必须在编译阶段失败。
3. 尚未登记的测试或扩展命令仍可通过字符串发送，但返回值固定为 `unknown`，直到其发布正式命令契约。路由器的运行时 schema、权限、来源和 manifest 校验全部保留；静态类型不能替代不可信输入验证。
4. 产品的 Unicode 字素分段、空白字素判断、整段计数和跨分块计数统一由 `src/core/text-counting.ts` 提供。编辑器、写作活动和文本所有者不再各自实现字符定义。
5. `StreamingGraphemeCounter` 只保留分块末端可能未完成的字素，不拼接整篇正文。精确大文本统计继续可取消、分块读取并定期让出主线程。
6. ADR 总索引记录当前状态和替代关系。历史 ADR 不删除；重复编号只改为唯一编号并在原文状态中保留说明。

## 兼容性

本决策不改变运行时消息封装、命令字符串、事务、历史、持久化或 `.echo8` 文件格式。字符显示语义继续遵循 ADR-0049 和 ADR-0059；`writingUnits` 兼容字段继续遵循 ADR-0051，但不作为产品主字符数。

## 验证

- 编译期测试证明已登记命令会推导返回类型并拒绝错误参数。
- 源码调用不再使用 `client.dispatch<TResult>` 或 `context.commands.dispatch<TResult>` 声称返回类型。
- Unicode 测试覆盖中文、组合附加符、空白和跨多个存储块拆开的 ZWJ 家庭 Emoji，并比较整段与流式结果。
- 类型检查、单元测试、Lint、生产构建和便携构建继续作为验收门禁。
